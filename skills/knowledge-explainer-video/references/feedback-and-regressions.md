# 已确认偏好与返工回归

## 复用边界

以下通用要求来自本项目多轮制作反馈。优先复用原则和检查方式，不把旧主题的颜色、角色、片长、具体稿件或工具宿主变成默认答案。用户后来对同一项的明确选择覆盖早期选择；例如 Git 片先关字幕、后来开启，当前沿用已启用状态。不得把曾尝试过的方案写成已认可方案。

### 通用制作标准

| 用户实际关切 | 制作动作 | 交付前怎么验 |
| --- | --- | --- |
| 要讲项目／知识，不是纯做动画 | 熟悉场景切入，明确问题、原因、操作、结果；每段一个主要认识 | 不听声音能看出操作，听声音能对应画面 |
| 用白话、自然口语 | 面向小白解释用途，术语随后出现；交付朗读稿不夹镜头指令 | 通读顺口，不能依靠语音加速塞满 |
| 迭代要有逻辑 | 仅适用演进型主题时使用“已有能力→解决了什么→剩余痛点→新办法→验证” | 版本变化有证据；不把所有知识主题硬拆成五次迭代 |
| 人物要简单，但有角色 | 锁定造型，按镜头准备透明姿势；指向、选择、递交、检查与协作 | 不带白底白卡，不固定站角落，不随镜头换长相 |
| 插画素材要丰富 | 人物及非人物都可生图，多做候选，选用风格统一的组件 | 数量不限于少量模板，但不上屏堆积；字体用可编辑图层 |
| 画面不要空，也不要低端装饰 | 放大有用物件、换景别、局部展开、缩短交互距离 | 不靠无关树木、花草、桌子、框中框填空 |
| 不要像 PPT | 让对象的状态变化解释知识，构图随动作重组 | 不仅是标题＋卡片淡入；新旧状态之间过程可见 |
| 要慢慢讲，也要动态有趣 | 人声确定节拍，运动有预备、过程、反馈和停留 | 关键结果读得清，微动不冒充知识推进 |
| 转场必须自然、多变 | 使用上一镜真物件承接，记录所有权和轨迹；按叙事关系选手法 | 没有硬切后补动画、双份锚点、文字瞬换、角色残留 |
| 图层不能穿模 | 电脑内容裁在屏幕内，容器前缘用真实轮廓遮挡，物件出入分层 | 起点、经过边缘、途中、终点都看，不能只看落点 |
| 连线要讲得通 | 单来源单目标、轴线到末节点、平行结果不乱分叉 | 箭头到达真实对象，线与标签不互压 |
| 重点要有视觉冲击 | 语义重点用尺度、差异、方向、景深层次和反馈强化 | 冲击后的阅读时间足够，不乱闪、不持续震屏 |
| 外部素材能融入 | 先识别素材内容和可用区间，再编排动画前后接力 | 不只贴一个播放框，不歪曲原片事实；见 footage-integration.md |
| 声音和画面配合 | 用正式录音切自然句；保留用户已选音色与情绪，合理去冗余 | 没有擅自改语速、重生成音色；合成音频须再次听 |
| 音乐要听得见 | 来源许可完整，按实际声音混音，重点句避让 | 听整段判断，不把固定增益值当验收 |
| 字幕按最终选择 | 默认开启但可关，真实语义断句，留安全区，导出 SRT | 无错词、越界、重叠、拆词、问句粘连；与录音同步 |
| 每次执行后审查 | 局部动作、两端镜头、完整预览分级复查 | 保存实际证据；未做的审查明确标待检查 |

### Git 项目专用，不自动复制到新主题

- 从 vibe coding 改坏网页切入，强调回退与多人协作。
- 素雅风格、已锁定人物；保持录音自然速度和字幕时间线。BGM 沿用最新明确选择，用户要求替换时从干净旁白重新混音。
- 存档不是简单保存所有改动；演出查看、挑选、说明、正式记录。
- 分支体现原版本与试验路径关系；回合前不能先亮“成功合并”。
- 冲突必须看见两人修改同一按钮、暂停、比较、人的决定；不能误导为 Git 自动替人做业务决定。
- 这支片子的分支路线是视觉比喻，不等于 Git 真的复制完整项目文件。
- 既有成片是基线，修订建立明确版本和回退入口；不覆盖用户已确认输出，不把未完成预览标成新成片。

## 返工闭环

### 最近一轮实现值得复用的检查

- 放大操作舞台时，指针、按钮、标注和关系线共用几何数据；不要出现界面变大而指针仍点旧坐标。
- 文件落入容器时前盖遮挡与到达反馈分层；反馈出现在接触之后，标签不与进度条或轴线相撞。
- 多人冲突把实际界面差异放大，人的选择之后让被选方案本身进入下一镜。静止的两张说明卡不能替代发生过程。
- 换歌使用原始旁白重混，保留片长和字幕时间；不把两首配乐叠在一起，不沿用旧曲的固定音量作为新曲的验收结论。
- 最终 MP4 与预览分别检查。完整解码、导出静帧抽查是技术证据，不是整片原速观看和试听完成的证据。

这些是从 Git 修订提炼的实现规则，不代表每次历史修订都已经经过全部验收；具体版本的通过项仍以实际报告为准。

每次反馈记录：用户原意／定位时间与组件／问题类别／修改范围／受影响的相邻镜头／复查证据／状态。区分“规则缺失”“规则已写未执行”“工具能力不足”，对应补规则、补执行闸门或说明限制。

满意的镜头登记路径、版本、起止时间和被认可的原因；只对同类镜头作基准。新表现方式先做带声音的短样片，已确认的方式不反复要求用户批准。不得把“用户未反对”记成确认。

评审结论分开写：代码与数据校验、静帧视觉检查、原速动态审查、音画试听、最终解码。没有执行的项不能打勾。修复遮罩不自动代表节奏通过；渲染成功不自动代表交付通过。
