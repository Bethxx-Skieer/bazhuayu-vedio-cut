# 知识动画的运动语言

## 先读这一页的用途

这是把动画十二原则转成知识讲解制作决策的工作规范，不是特效套餐。先定义观众要看懂的变化，再决定动作；不要求每镜用全十二条，也不以“动得多”代替讲清楚。静态优雅与动态有力可以同时成立。

需要解释动画为什么这样设计，或返修“像 PPT”“说明浅薄”“不够华丽”时，先读 [visual-revision-logic.md](visual-revision-logic.md)：用语义变化、因果反馈、注意力顺序、对象连续性、阅读分工和证据层级定位问题，再从本页选择运动方法。

## 十二原则：怎么做，怎么判断

| 原则 | 在知识动画里的做法 | 禁用误区与检查 |
| --- | --- | --- |
| 挤压与拉伸 | 软质标记、落地反馈可短暂变形；采用逆向缩放维持近似面积。硬质电脑靠位移、阴影和接触反馈表达重量。 | 不拉扁汉字、截图、人物脸或整块 UI。检查恢复后的尺寸及接触面；不必每件物体都弹。 |
| 预备动作 | 操作前先让目光、指针、选中轮廓或短暂提起指明对象，观众知道谁要动。 | 不提前展示结论。检查没听懂旁白时能否找到动作发起者。 |
| 演出布局 | 为每个语义节拍确定一个主焦点；人物朝向、对象尺度和留白共同指向它。 | 不把所有内容一次铺开。缩小预览后仍能认出“谁对什么做什么”。 |
| 连续动作与关键姿态 | 先锁起始、预备、接触、结果、停留、交接六类关键状态，再补中间帧；不适用阶段可省。细小尾随运动在结构通过后补。 | 不能只做好两张静态图再加淡入。拖动时间线到任意帧都要得到确定结果，不依赖播放历史。 |
| 跟随与重叠动作 | 主物先到，附属标签或柔软边缘稍后收稳；交接时旧场景的收尾与新场景的准备有序交叠。 | 不是所有对象同时弹，也不是人物换姿势时叠出两个身体。文字阅读阶段必须稳定。 |
| 缓入缓出 | 起步、制动和落位有速度变化。连续经过一个中间点时保持速度方向，不把每小段都 ease-in-out 到零。 | 时间连续不代表速度连续。检查接缝两侧的逐帧位移，排除突然加速、停顿、倒退。 |
| 弧线 | 搬运、递交和人物手势围绕明确支点走弧；道路、连线上的对象沿真实路径运动。 | 软件滑块、硬轨道可走直线。不能为了弧线穿过屏幕边框或第三件物体。 |
| 次要动作 | 角色眼神、指针按下、节点响应为主要变化提供原因或结果；主动作停稳后可有一次轻微回应。 | 禁止无意义的循环漂浮、抖动、闪光抢焦点。移除次动作后主逻辑仍成立。 |
| 时间节奏 | 区分动作总时长与逐帧间距：前者由语句和理解时间决定，后者决定速度、重量和力度。 | 不压缩人声追画面，不把统一秒数当合格标准。分别正常速度看画面、音画合看。 |
| 夸张 | 在关键词处扩大局部差异、拉近镜头或强化前后对比，让“改变了什么”一眼可见。 | 强调幅度可以大，信息出现不能短到读不清；不用震屏和高频闪烁掩盖没有内容。 |
| 扎实造型 | 明确接触点、支点、透视、屏幕内区、容器前后层；图像物件按真实轮廓拆前景遮罩。 | 轴对齐包围盒不足以证明不穿模。检查运动扫过区域、遮罩边缘、字幕区及投影关系。 |
| 吸引力 | 统一造型语言，变化景别、比例、方向与张弛；主角的操作推进故事。 | 不是添加更多装饰或每镜换特效。完整连看时既有重点段的力度，也有解释段的从容。 |

## 动作谱：分镜到代码之间必须多这一层

每个复杂动作填写 assets/motion-score.template.json 所示结构。它是旁车文件，不改变旧项目清单格式；未填写的旧项目仍可读取，但不能把空白动作谱标成已审查。

必须能回答：

1. 哪句话的哪个词触发动作？来自实际录音的时间点是什么？
2. 谁是主角对象（持久 ID），起始状态、目标状态是什么？
3. 预备、主运动、接触、反馈和理解停留各占什么时间？
4. 主体走什么路线？是否经过容器边界？前后遮挡由谁负责？
5. 主对象、次对象、镜头分别何时运动？谁先谁后？
6. 什么时候能看见结果？不是用出现的勾代替尚未完成的操作。
7. 交给下一场景的是什么？谁持有它的绘制权？如何证明没复制两份？

命名以语义为主，如 selected-login-file、trial-version、chosen-solution；不要只叫 card1。同一物件跨镜头移动时保持 ID、外观和必要内容；多个渲染器接力时，只能有一份可见权威副本。

## 转场不是选一个预设

按叙事关系选择，并先写清承接物、坐标系、缩放、旋转、方向、时刻和遮挡。

- **同物交接**：上一镜的文件被提起、递交，成为下一镜主角。物件持续可见，其他内容分批退出。
- **局部展开／收束**：放大已有窗口进入细节；讲完缩回原物件。镜头与物件不要同时无理由反向运动。
- **路径接力**：沿现有关系线跟随消息或版本，再让终点展开下一段空间；节点不能未到先亮成功。
- **形状／构图匹配**：保留位置、轮廓或视觉重心，引导“这是同一个东西的另一种视角”，不能暗示不真实的概念等同。
- **遮挡揭示**：用当前有意义的前景物或其轮廓揭示新空间。遮罩前沿必须连续，不能借全屏色块偷偷硬切。
- **方向延续**：相邻镜头保留动作方向，再调整景别。揭示全景后给眼睛重新定位的时间。
- **章节重置**：只有明确换主题才用有停顿的简洁切换；保留声音或色彩线索，不强造无意义变形。

整片记录转场序列及理由，检查是否连续几次机械重复。同一种手法可以复用，不设“必须集齐几种”的指标。不同手法仍服从同一速度气质、配色和物件逻辑。

### 连续性的四个层次

- 语义连续：物件为什么从这里去那里？
- 几何连续：交接前后的位置、尺度、方向和遮罩是否对齐？
- 运动连续：两侧速度是否相容？若要停顿，是否有明确落位与阅读理由？
- 感知连续：观众是否还能跟住它？移动中换字、复制锚点、镜头与对象抢跑都会破坏这一层。

对于无停顿交接，至少比较交接前后各 2–3 帧的中心位移和尺寸变化；允许阈值按物件大小、运动速度记录，不宣称像素阈值能自动判断审美。

## 动态构图与密度

先写“镜头带观众看什么”，再生成该过程的关键帧。不先做满屏卡片再给卡片进场。

全景交代关系 → 局部观察变化 → 动作跟随 → 结果特写 → 返回关系总览，是可选语言，不是固定五步模板。空旷时先检查主体尺度、操作距离、信息层级和镜头，而不是添花草纹理；拥挤时分批揭示，不压小文字。人物不必常驻，必要时让真实证据成为主角。

能量变化要有理由：问题出现时聚焦，解释时慢下来，结果时明确反馈，转折时换视角。素雅约束的是外观，不是把动作削成 PPT；酷炫来自清楚的空间转换和因果反馈，不来自频繁闪白。

## 工程落实与评审

复杂容器、镜头与指针联动、多人选择的实现前，读 [interaction-contracts.md](interaction-contracts.md)。重点不是再增加动画数量，而是固定同一物件的坐标、接触点、图层所有权及可见结果。

- 所有状态由帧号及统一旁白时间线推导。随机值需固定种子；避免依赖浏览器时钟、CSS 自运行循环或前一帧副作用。
- 运动图层与文字图层分开，必要时文字退出后再变化载体；避免文字变形或瞬间替换。
- 大范围位移先检查路径，容器接触先检查遮罩，再补柔和回弹、残余运动与细节音效。
- 边界三帧只检查切口；复杂动作还需预备／离开／途中／接触／反馈／停稳帧，以及整段正常速度播放。
- 原速检查节奏，慢放检查图层；静帧、类型检查、文件解码都不能证明原速流畅。
- 修一处后重看前后相邻镜头和整片，不留下局部风格升级、其他段落仍像模板的断层。

## 学习来源与适用范围

十二原则名称与基本含义参照 [Adobe 动画原则](https://www.adobe.com/creativecloud/animation/discover/principles-of-animation.html)；界面状态变化与动作衔接参考 [Microsoft 动画原则](https://learn.microsoft.com/en-us/windows/win32/lwef/animation-principles) 和 [Adobe 关于动效设计的讨论](https://blog.adobe.com/en/publish/2016/11/08/redesigning-the-12-principles-of-animation-for-motion-design)。上面的知识动画落地规则与检查项是本项目针对返工问题的综合设计，不声称是原作者原话。

用户指定的 [Table-VideoSOP](https://github.com/duoduoler-ops/Table-VideoSOP) 提供了“先设计观看过程、以已确认样片对标、交付后复盘”的参考方向（文档 CC BY 4.0；代码 MIT）。此处为适配本工作流的独立总结，不复制其提示词或素材；不移植其手动生图流程，也不把参考片里的视频模型生成片段当成本项目必须实现的能力。记录参考片的实际文件与时间码后，才可声称分析了对应镜头。
