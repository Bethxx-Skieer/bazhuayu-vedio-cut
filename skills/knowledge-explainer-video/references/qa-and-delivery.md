# 质检与交付

先按 [feedback-and-regressions.md](feedback-and-regressions.md) 核对历史易错项。复杂动作旁车用 `scripts/validate_motion_score.py` 检查，它只验证计划数据，不判断画面流畅。另记录几何检查、静帧审查、原速动态观看、音画试听、最终完整解码各自的证据与待办；禁止用其中一项通过代替其他项。

连续交接加查前后各 2–3 帧位移与尺寸，捕捉速度突变；动作加查预备、离开、接触、反馈与停稳阶段。旧版成片通过不意味着修订版通过。所有修复都复查相邻镜头，最后检查全片节奏与风格一致性。

## 正式渲染前

固定检查：

1. 开场、核心解释和结尾代表帧；
2. 第二次确认使用的 8–12 秒转场样片；
3. 全片低清预览；
4. 每个场景边界的前一帧、切换帧和后一帧；
5. 每个复杂交互的动作起点、中间状态和落点；
6. 最长文字、最复杂关系图、人物最大和最小尺寸；
7. 所有真实视频的裁剪、许可和内容对应关系。

## 自动检查

- `validate_project.py` 无 error；
- 内容和视觉两次确认均为 approved；
- 正式成片存在人工录音音轨；
- 视频为清单指定画幅和帧率；
- 最终时长与清单及人工录音一致；
- FFmpeg 完整解码无错误；
- 视觉覆盖、纯文字占比、转场时长和场景连接满足清单；
- 所有选定资产存在，网络真实素材有许可与来源。
- 启用字幕时，Caption JSON 时间有序且无重叠、内容不空、末尾不越界，并已生成独立 SRT；启用音乐时有文件、来源与许可。

使用：

```bash
python scripts/qa_render.py project-manifest.json final.mp4 work/qa
```

脚本生成媒体报告，并为每个场景边界提取三帧。自动报告不能代替人工视觉判断。

## 人工检查

- 讲解是否从问题与价值出发；
- 每个观点是否有“人物或物件 → 操作 → 可见结果”的易懂画面；冲突等机制是否演出了发生过程，而非只显示结论；
- 图片丰富但是否仍能慢慢看清；
- 人物外观、姿势和表情是否连续，是否与物件真实互动，而非固定站在展示框旁；
- 转场是否由上一画面自然演变；
- 是否存在穿模、提前出现、残留、闪屏、文字硬替换、图层遮挡、轴线缺口或箭头歧义；复杂动作的中间帧必须检查；
- 真实视频是否真正证明或说明当前内容；
- 字幕是否与人工录音一致、自然断句且无遮挡；音乐是否有存在感而不妨碍每句旁白。

产品能力片另按 [visual-revision-logic.md](visual-revision-logic.md) 核对语义变化、因果反馈、焦点与证据：真实窗口是否保留上下文，报告指引是否跟随口播并定位到对应记录，机制示意和等待压缩是否可辨识。字幕返修按 [captions-and-readability.md](captions-and-readability.md) 查字体、底板、短句间隙及深浅场景，并从实际输出检查原尺寸和 640×360 可读性。

完整观看最终成片，并在局部修复后重新查看相邻镜头和整片。报告中记录发现的问题、修复位置、复查证据和人工审片结论；自动提取帧与完整解码不能代替观看。

## 交付

正式导出及换音乐的检查见 [audio-and-export.md](audio-and-export.md)。从最终 MP4 抽帧和完整解码，并用 `assets/revision-review.template.json` 记录本版证据；上一版审批不能覆盖新修订。文件已导出但尚未完成全片试听时，可提供文件并明确状态，不能升级为 `qa_passed`。

交付最终视频、讲稿、启用时的烧录字幕视频与独立 SRT、来源与许可表、分镜、选定图片、角色设定、质检报告和可复现 Remotion 工程。候选图、下载缓存、静音预览、失败渲染和旧版本保留在 `work/`，不进入正式交付，也不提交 Git。
