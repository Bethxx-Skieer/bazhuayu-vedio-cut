# 配乐匹配、混音与 MP4 导出

只处理声音与导出时沿用现有工程、已确认讲稿及画面，不更换框架、不升级依赖、不重新生成配音。用户指定的新选择覆盖旧音乐偏好，不把 Git 项目的某首歌、音量或片长写成通用参数。

## 选音乐：匹配讲解，不仅匹配画风

先核对正式录音与当前成片。听开场、解释最密集处、主要转折和收尾，再比较候选的速度感、乐器音色、旋律密度、重拍强度及情绪走向。

- 素雅知识片可优先试听轻量器乐、自然音色和较少主旋律的方案；不强制某类乐器或固定 BPM。
- “自然”通常意味着音乐与语言呼吸相容，不是音量极低；“酷炫”也不等于全程强鼓点。
- 先做覆盖稀疏旁白与密集解释的混音短样，不能只听裸音乐。若用户已授权自主选择，无须强制再确认歌名。
- 音乐节拍可辅助接触、反馈和章节落位，但旁白是讲解的主时间源，不为踩鼓点改人声速度或抢先揭示结论。
- 网络来源需核验具体曲目的许可与署名要求；“royalty-free”不自动代表无需署名、可商用或可任意再分发。
- 记录作者、曲名、原始页面、许可及版本、取得日期、本地路径、哈希、所用区间、剪辑或变速等改编情况。需要署名时把可直接粘贴的文本与成片一起交付。

## 换配乐要从干净音轨重建

1. 找到正式干声、已批准音效和当前音乐分别来自哪里，确认源视频是否自带音轨。
2. 从干声及必要音效重混；不能在旧的“人声＋音乐”混合文件上再叠新歌。
3. 没有干声时，先查当前工程的分轨；找不到则说明限制、请求原始录音。不要擅自用消音结果替代用户原声。
4. 保持人声样本节奏、字幕时间和视频总时长不变。音乐可按许可做剪接、淡变或轻微保调变速；先试听音质，不把音乐处理施加到总混音。
5. 音乐不够长时优先选完整合适的区间或乐句交接；循环点检查音高、节拍和残响，禁止直接在任意采样点硬接。
6. 开头渐入、结尾自然收束；结尾不能为了保留乐曲而拖长已结束的讲解，也不能切掉人声末字。

混音时先建立音乐存在感，再按人声调整避让。过快释放会造成音量喘动，过强避让会让音乐反复消失；检查句间、轻声句和长解释段。削峰、响度测量和频段调整只是辅助，不能凭固定 gain 或某个响度数值宣布好听。耳机与普通外放至少分别抽听重点区间；无法试听时在报告中保留待办。

## 导出前锁定的是一个版本组合

在项目记录中写清：composition ID、入口文件、画幅、帧率、帧数、当前干声与混音文件、字幕文件、输出路径、渲染命令、依赖锁文件。不存在的字段写明未知或不适用，不能把旧成片的审批借给新修订。

导出请求本身不等于允许重做动画。用版本化文件名保留旧成片；目标已存在时先确认是否为同版本，避免静默覆盖。只换音轨且视频和烧录字幕均未变时可复制视频流重封装；只要画面或烧录字幕有变，就重新渲染画面。

推荐交付基线为 MP4、H.264、8-bit 4:2:0、AAC，画幅与帧率服从项目。已有 Remotion 工程优先用本地锁定版本，不为一次导出去升级依赖。CRF、音频码率和并发度根据内容及机器选择，不将一个项目的参数当硬指标。

## 验证真正输出的 MP4

预览工具播放正常不等于导出文件正确。对最终文件检查：

- ffprobe：视频编码、宽高、帧率、像素格式、音频编码／采样率／声道、音视频各自时长与容器时长；目标音轨数量和内容符合方案，没有旧音乐额外叠入。
- 时长：与 `durationInFrames / fps` 及正式录音核对。AAC 可能有少量编码填充，记录流时长与容器时长的差异；不能为了凑整数秒裁掉末字或悄悄拉伸声音。
- 完整解码：用 FFmpeg 检查整段音视频，不只探测文件头。可用 `ffmpeg -v error -xerror -i final.mp4 -map 0:v:0 -map 0:a:0 -f null -`；静音预览不强制映射音频。
- 像素格式：`yuvj420p` 可表示全范围 8-bit 4:2:0，并不单凭这个名字判定损坏；同时核对 color_range 和实际播放。若交付平台明确要求 limited-range，则正确转换并复查黑白层次，不能只改标签。
- 从输出 MP4 重新抽边界与复杂动作帧，确认所看的确是该版成片；接触表用于排查静态关系，不作为连续动画通过证据。
- 原速查看输出文件并试听，核对字幕、配音、音乐、末尾淡出和关键动作；尤其检查旧缓存、错 composition、音频重复及新旧字幕混用。

## 证据与交付措辞

使用 assets/revision-review.template.json 分开记录数据检查、几何检查、导出静帧、原速动态、音画试听、字幕及完整解码。每项保存执行范围和证据；未做为 pending，确实不适用才用 not-applicable 并写原因。

只有完成导出及技术检查：可以说“MP4 已导出，完整解码通过”，同时保留尚未做的审片项；不能标记 qa_passed。完整审片通过后才更新正式交付状态及最终文件入口。用户只要 MP4 时可直接提供文件，不用扣住导出来等待无关的创作确认。

交付简洁说明版本、时长、画幅、字幕与音乐是否包含，给出本地文件链接／预览及必要署名文本。不自动上传云端、推送 Git、提交音频原件或清理旧版本。
