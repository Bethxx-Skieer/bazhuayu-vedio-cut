# 画面与动画优化的推理框架

用于产品宣传讲解、真实录屏与动画混合制作，以及“像会动的 PPT”“效果不够丰富”“演示浅薄”“看不清”的返修。以下是从制作反馈提炼的设计判断方法；具体运动原则见 [motion-language.md](motion-language.md)，坐标与遮挡实现见 [interaction-contracts.md](interaction-contracts.md)。本页回答先改什么、为什么改，不要求每镜集齐全部手法。

## 一、动画首先表达一个变化

先写出：**观众原先知道什么 → 谁因为什么发生变化 → 哪个可见结果让观众获得新认识**。若前后只多了标题、装饰或入场卡片，动画可能增加了运动，却没有推进解释。

把一个语义节拍写成：`口播触发词 → 主体对象 → 状态变化／操作 → 可见反馈或证据 → 理解停留 → 下一镜承接物`。沿用现有分镜和动作谱记录即可，不另造一份平行时间线。主题不涉及实际操作时，变化也可以是分类、比较、关系显现或观察视角改变。

例如“问题交给数据工具”不能只让工具 Logo 弹入：先保留已有的问题与字段，展示它们进入任务，然后由真实执行状态或明确标注的机制示意说明发生了什么。采集结果与分析结论具有不同含义，不能仅靠变形把二者当作同一件东西。

## 二、六项动画逻辑

| 判断维度 | 设计理由 | 改动方法与验收 |
| --- | --- | --- |
| 语义变化 | 动作的价值来自观众理解到的新关系 | 找出输入、筛选、聚合、对照、引用等真实变化；去掉动画后若仍只是同一张说明卡，检查是否缺少过程 |
| 因果与反馈 | 观众需要知道结果为什么出现 | 操作／输入先发生，状态响应与结果随后出现；排队、执行、返回、分析分开，不能提前亮成功，也不能把额外人工指令隐去 |
| 注意力顺序 | 同时改变多个焦点会增加寻找目标的负担 | 每个节拍确定一个主焦点；用位置、尺度、对比或指引建立顺序，非焦点稳定或降低对比；镜头、主对象和文字不要无序同时运动 |
| 对象连续性 | 能跟住同一对象，才容易理解前后关系 | 保持语义 ID、外观线索与必要内容；跨镜交接保持坐标、方向和唯一可见副本。生成新对象或复制时明确展示来源，不把不同记录偷换成一个对象 |
| 阅读与动作分工 | 移动中的小字和刚出现的结果都需要重新定位 | 组织为引导、动作、落位、阅读、交接；解释复杂时延长稳定阶段。画面丰富可以来自视角和状态变化，无需让所有元素持续漂浮 |
| 证据层级 | 示意能解释机制，真实记录才能证明本次执行 | 口播说操作时给操作，说结果时给对应记录，说判断时给支撑它的条目。示意、真实界面、回答摘录与作者解读明确区分 |

这些维度相互约束：强烈的尺度变化应保留对象连续性；增加演示深度应保留阅读时间；更华丽的反馈也不能越过真实因果。

## 三、先诊断，再增加组件

| 反馈 | 常见原因 | 优先修改 | 不应作为主要补救 |
| --- | --- | --- | --- |
| 像会动的 PPT | 只有“新标题＋新卡片”，对象没有经历操作 | 让同一对象经过输入、处理、响应、结果；布局随过程重组，再连接下一镜 | 给所有卡片加弹簧或频繁切模板 |
| 不够华丽／专业 | 大小、景别、运动节奏单一；关键结果缺少强调 | 在语义重点安排局部展开、路径跟随、遮罩揭示、前后对照、结果落位与短暂反馈；细节动作服务主动作 | 默认改成玻璃、金属高光、强光晕或装饰粒子 |
| 说明浅薄 | 讲了概念和结论，缺少执行过程及可追溯证据 | 补上真实需求、执行状态、返回记录、报告证据中缺失的环节，并逐句对应口播 | 延长抽象流程动画或机械增加录屏秒数 |
| 录屏不真实／不完整 | 长期过度裁切，失去应用、问题和结果的上下文 | 先展示完整相关窗口，再定位区域；需要细节时保留全景并加局部放大或旁侧释义 | 全程只露一行字，或伪造未录到的点击与输入 |
| 报告讲不明白 | 页面被当作静态背景，观众不知道看哪里 | 依次定位问题、答案、品牌或引用，再落到业务解释；使用同坐标系的框选与连线 | 同时把所有表格行、数字和链接点亮 |
| 清晰度差 | 源文件、渲染缩放、编码或播放器显示其中一环不足 | 逐环核对，并从实际 MP4 抽帧判断；保留原始素材，减少重复转码 | 给低清输出改文件名为高清，或仅上采样 |
| 画面杂乱／节奏急 | 镜头运动、主物运动、标题替换抢同一焦点 | 错开触发点、降低非重点对比、增加落位后的稳定时间 | 继续叠加标签或统一加快动画 |

## 四、把理论落实到产品宣传片

### 传播顺序

开头尽早让观众理解业务问题、观看收益和产品名称；前约十秒可作为检查区间，不能为满足固定秒数挤压口播。痛点应可感知，例如重复提问、复制回答与整理证据，而非泛泛宣称“效率低”。

中段用一个连续案例连接需求、执行、数据与洞察。结尾回答“观众现在能做什么”，引导了解或试用；网址、二维码只用已核验入口。宣传力度来自清晰能力和可信结果，不扩大样本口径、不暗示录屏没有发生的自动化。

### 选择画面载体

| 当前口播要完成的事 | 适合承担主画面的素材 |
| --- | --- |
| 提出业务问题 | 真实需求、问题卡或具体使用场景 |
| 解释系统怎样组织工作 | 有真实字段依据的组件动画；未录到的过程标为机制示意 |
| 证明任务执行及返回 | 真实操作录屏、状态变化和返回记录 |
| 解释数据处理口径 | 实际记录与筛选／分组动画对应，显示保留和排除的原因 |
| 展示结论与机会 | 原报告、逐题证据、同步指引与简短业务解读 |

不固定“动画占多少、录屏占多少”的跨项目比例。占比随证据完整性与阅读需要调整；慢放、定格和等待压缩要可识别，不能把成片时间当作产品实际耗时。

### 完整窗口与报告指引

- 先保留可辨认的应用／网页上下文，窗口保持比例。字幕区、标题区和证据区域分别留空间；不要套多层电脑外壳挤小内容。
- 手机端不能读完整页时，保留窗口作上下文，用一个重点框和较大的忠实摘录承担精读。摘录与原文一一对应，译文或释义标明性质，不把重绘文本冒充原录屏。
- 指引按“定位 → 强调 → 解释 → 交接”展开。例如口播到品牌提及数时突出对应列；到具体场景时定位问题行与回答；到引用时定位链接并区分“存在链接”和“已核验网页”。
- 高亮框、箭头、旁侧解读共用实际内容的几何数据，随窗口缩放或页面滚动更新。源页面运动时不能让框停在旧位置；采用定格讲解时在片中标明。
- 结果数字标出样本范围、识别依据和必要的缺失说明；未给排名不能解释为排名差。内容机会是基于样本的解读，不扩大为市场全貌。

### 丰富的组件与克制的材质

可用组件包括任务输入、问题组织、执行状态、数据行筛选、关系连线、证据定位和报告对照。组件的丰富来自不同功能、状态和相互作用，不是同一张卡片换颜色。优先设计可解释的空间变化，再补层次、速度差、局部反馈与少量装饰。

本次 Data Hub 项目选择蓝色主体、较丰富的程序动效，用户排除玻璃和金属高光。把这些作为该项目的视觉约束，其他项目仍服从各自已确认方向。用户要求更华丽时先增强构图和运动逻辑，不擅自换材质、角色或框架。

## 五、画面优化闭环

1. 定位反馈对应的时间、口播句与认知任务，指出是逻辑、证据、焦点、连续性还是清晰度问题。
2. 写修改前后观看过程，列出保留的真实依据、变化对象、动作触发、结果出现与阅读停留；复杂动作沿用动作谱。
3. 先修结构：主体大小、焦点顺序、状态变化、证据和交接；结构成立后再加细节动效。不要只升级开场，检查中段演示和结果段是否形成风格断层。
4. 抽看动作起点、中间、落点与场景边界，另原速观看含前后语义的连续区间。分别判断静态审美、动态可跟随性、口播对应与事实准确。
5. 从最终编码文件检查 1080p 实际细节，并用 640×360 预览检查字幕、品牌、关键数字及引导重点。UI 小字无需全部可读，但旁白依赖的证据必须可定位、可精读。
6. 记录本次修改及检查范围。全片解码、静帧、局部播放和完整音画审片分开记；局部优化通过不等于全片终审完成。
