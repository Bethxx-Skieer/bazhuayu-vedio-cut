# 组件交互与镜头协同

在动作谱已确定后、编写复杂场景之前阅读。本文件处理组件如何真正配合；运动原则和转场选型仍以 motion-language.md 为准。下列 Git 例子是回归场景，不是每个主题必须使用电脑、文件盒或按钮。

## 先写交互契约

对每个需要搬运、选择、进入容器或跨镜交接的物件，记录以下信息，可放在项目工作记录或动作谱说明中：

| 信息 | 必须回答的问题 |
| --- | --- |
| 语义身份 | 是同一份内容移动，还是复制、生成新内容？若复制，何时产生副本？ |
| 坐标系 | 坐标属于屏幕、物件父层还是整个画布？相机变换由哪一层承担？ |
| 接触点 | 指针／手指碰的是按钮内部、文件抓取点还是容器入口？ |
| 可见所有权 | 起点、在途、落点各由哪个组件绘制？切换时不得双份，也不得空一帧。 |
| 边界与遮挡 | 屏幕内区如何裁切，容器前缘怎样遮挡，何时从内层转到全局层？ |
| 可见结果 | 哪个状态证明操作完成？反馈是否晚于动作而非提前出现？ |
| 退场与回退 | 下一镜接走什么，其余角色、指针、标签各何时退出？ |

## 容器出入：屏幕、窗口与档案盒

推荐按语义分层：容器后部 → 容器内内容 → 前缘遮挡 → 解释标注。正在外部搬运的物件由单独运动层持有，进入后再交还内层。字幕固定在全片安全区，不随场景相机缩放。

- 屏幕内可用区应从实际素材确定，不把整张电脑图片的矩形当作屏幕。圆角或透视明显时使用贴合轮廓的裁切。
- 容器前缘使用真实轮廓遮罩；不能拿一块白色矩形冒充前盖，遮住插画纹理和边线。
- 物件离开屏幕时，先让外层物件与内层物件在世界坐标中完全重合，再转移绘制权。不能解除裁切后突然跳位置。
- 进入档案盒时文件下部应逐渐被前盖遮住；接触反馈可在背层，文件名称或说明放在不会被误挡的独立标注区。
- 包围盒可以发现越界，不能证明曲线轮廓无穿模。另查透明边缘、前盖开口、阴影和运动扫过区域。

重点抽帧：离开前一帧、接管帧、离开后一帧、经过边界最深处、接触前后、停稳。若相机也在动，使用最终画布坐标检查，不仅看组件局部坐标。

## 推近时，所有相关组件一起变换

放大操作区域是解决空旷和信息过小的方法，但不能只放大背景界面：指针、被选对象、定位括号、关系线端点要引用同一几何数据。

- 用同一变换或坐标换算驱动物件及指示器；平移缩放时，世界坐标为“父层原点 + 局部坐标 × 缩放”，嵌套旋转或非默认变换原点时使用完整矩阵。
- 指针从实际目标框取点，不硬写一组在原尺寸下刚好正确的数字。镜头放大后再核对点击位置。
- 连线在物件边缘终止，不穿过正文；跟随物件变化更新端点。已不再有解释作用的线应退场。
- 镜头负责引导目光，主体负责完成操作。可先推近并停稳，再操作；需要同时运动时，把它们设计成同一个可跟踪的路径，而不是两个独立弹簧。
- 返回全景后，主体位置与关系仍应与前一全景一致。不要在缩回过程中偷偷换成另一份结果卡。

## 选择、冲突与多人协作要演出过程

把“两个输入 → 同一目标上的差异 → 暂停 → 比较 → 人的决定 → 结果交接”作为可用模式，不只放两个标题和一个勾。

以两个人修改同一按钮为例：先展示各自实际修改，再把同一位置的差异放大；暂停信号只在两份修改相遇后出现。人物或指针指向被选择的具体方案，未选方案降级或退出。被选界面本身承接下一镜，不能另造一个无来源的“完成”卡片。

如果知识事实允许保留双方修改，就展示组合过程；不要让视觉默认所有冲突只能二选一。人的决定与系统执行必须有不同的视觉角色。

## 丰富与冲击：修改整个观看过程

每段先列“关系全景／局部操作／结果强调／交接”中真正需要的景别，并写下变景别的旁白触发点。不要求固定顺序或集齐所有类型。

- 小物件突然孤立出现：优先从前一镜已有物件提取或移动过来，让来源可见。
- 大字镜头好看但前后生硬：让前镜的线、边缘或同一物件建立方向，再出现关键词；退出时把可识别元素交给下一镜。不要硬把不相干概念变成同一物体。
- 画面空：先调整主体比例、交互距离和裁切；不要先添背景装饰。
- 动作弱：突出真正的前后差异，加清楚的接触反馈；不叠加无意义粒子。
- 动作乱：检查是否同时发生镜头运动、主物位移、标题替换与多角色入场，错开抢同一焦点的变化。
- 画面升级不均：列出全片每段的主要操作、最大景别变化、转场承接物和理解停顿。对照检查，不把所有力度集中在一个示范镜头。

## 局部实现后怎么审

先原速观看含前后各一段语义的区间，确认看得懂；再慢放查遮挡、指针落点、文字层与运动接缝。类型检查只能证明代码合法，几何测试只能证明所测关系成立。记录具体时间码、修复前后状态及实际看的证据，不写“无穿模”而只附一张静止截图。
