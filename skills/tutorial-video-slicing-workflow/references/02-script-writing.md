# 阶段二：脚本策划与时长规划

## 目标

把文章、报告和素材证据重组为观众能够独立听懂的唯一旁白脚本，并在正式配音前控制信息密度和预计总时长。

## 输入

- 已通过的素材证据库；
- 可证明事实和画面缺口；
- 目标观众、平台、时长、语气和行动目标；
- 用户指定必须保留或删除的表达。

## 写作要求

1. 从用户任务和业务价值出发，不照读宣传文章。
2. 每个完整自然句只表达一个主要动作、判断或结果。
3. 关键任务写清“需求或输入 → 调用或执行 → 稳定结果”，不必展开没有信息价值的等待过程。
4. 区分直接结果、业务判断和未经证实的最终效果；不要补写素材不能证明的承诺。
5. 总览版强调主线和代表场景；详解版再展开输入、执行、分析和结果。
6. 多类能力逐项介绍时，保证每类至少有一句明确作用和一个结果方向；时间不足时减少细节，不用快速闪屏硬塞。
7. 抽象概念可以保留，但在画面备注中标记为动画或结构组件。
8. 专业名词只保留理解所需部分。项目专属读法暂存于发音表，不为了 TTS 改坏显示文案。
9. 结尾回到业务决策、流程连续性、效率或经验复用，不重复前文列表。
10. 自然断句的显示文本结尾不使用任何标点符号；句中可以保留理解所需的逗号、顿号、冒号、引号等。旁白停顿和特殊读法另存到 `ttsText` 与停顿策略，不用显示文本的句末标点驱动。

## 自然句与规划时长

为每个自然句分配稳定 ID，并保存：

| 字段 | 要求 |
|---|---|
| `sentenceId` | 如 `N001`，后续不随文案微调改变 |
| `spokenText` | 观众实际听到的文字 |
| `purpose` | 钩子、解释、场景、结果、过渡或结尾 |
| `targetDurationSec` | 按已确认惯用语速估算的目标时长 |
| `visualIntent` | 素材、报告、动画或混合 |
| `evidenceIds` | 支撑该句的素材 ID |

目标时长用于规划，不是正式时间码。检查：

- 预计总长是否符合用户目标；
- 各业务场景是否得到足够解释时间；
- 输入和结果是否都有时间出现；
- 是否存在必须依靠过快朗读才能放下的句子。

## 用户确认闸门

在进入配音前向用户交付：

- 唯一旁白脚本；
- 自然句划分；
- 各句目标时长与预计总时长；
- 每句拟用素材或动画类型；
- 特殊词初始清单。

用户修改文案时更新同一份脚本，不创建“最终版2”“最终最终版”等并行来源。保留版本号，但只有一个 `activeScriptVersion`。

## 禁止事项

- 脚本未确认就批量生成正式配音；
- 根据字数估算直接锁死字幕时间码；
- 为了适配现有素材删掉业务链必需信息；
- 把项目营销口号当成已经验证的业务效果；
- 同时维护旁白稿、字幕稿和 TTS 稿三套不同文案。

## 通过条件

- 用户确认脚本、节奏和预计总时长；
- 每句都有稳定 ID、目标时长和证据或动画方向；
- 特殊词已经进入待试听清单。

通过后把项目状态更新为 `script_locked`。
