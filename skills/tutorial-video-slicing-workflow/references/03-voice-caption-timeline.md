# 阶段三：配音、字幕与正式时间线

## 目标

先锁定声音，再生成实际配音，并以真实音频时长建立唯一字幕时间线。字幕文字与实际朗读完全一致，同时允许 TTS 使用不污染显示文本的发音别名。

## 四层文本

每个自然句分别保存：

| 字段 | 用途 |
|---|---|
| `spokenText` | 用户确认的实际旁白文字 |
| `displayText` | 字幕显示文字；词语和顺序必须与 `spokenText` 一致 |
| `ttsText` | 发送给 TTS 的文本，可替换特殊读法和控制停顿 |
| `pronunciation/pausePolicy` | 特殊词别名、声调、连续朗读或停顿规则 |

`displayText` 与每个字幕 cue 的结尾一律不保留标点符号；句中可以保留理解所需的逗号、顿号、冒号、引号等。除删除句末标点外，不得增删或改写词语。引号、书名号等显示符号不能未经确认制造异常停顿。

## 声音锁定闸门

正式全文配音前生成一段代表性试听，至少覆盖：

- 所有特殊词、英文缩写和数字；
- 最长自然句；
- 用户要求的最终语速；
- 引号、顿号、破折号等可能影响停顿的符号；
- 一处句间衔接。

保存音色、提供方、语速、情绪、特殊词读法和试听文件。用户确认后更新为 `voice_style_locked`；不得静默更换音色或提供方。

## 正式配音

1. 按完整自然句生成音频，不按短字幕 cue 切碎语音。
2. 记录每句原始音频时长、必要的轻微调速和最终时长。
3. 短句之间补自然静音；轻微超出目标时长时可以在用户接受范围内调速；明显超出时先改文案或重新生成。
4. 不截断句尾，不用剧烈加速强塞进预估窗口。
5. 合成完整配音后检查错读、异常气口、音量漂移和句尾完整性。

完成后保存逐句音频、完整 WAV 和配音报告，把状态更新为 `voice_generated`。

## 生成正式字幕时间线

1. 以实际配音的句子起止时间作为正式时间轴。
2. 长自然句可以按语义和屏幕宽度拆成多个显示 cue；cue 边界应接近实际朗读的短语边界。
3. 每个 cue 保存 `cueId`、`sentenceId`、`startSec`、`endSec` 和 `text`。
4. 同一句的 cue 按时间拼接后，文字必须等于该句 `displayText`。
5. 横版和竖版共用 cue 文案与时间，只改变布局。
6. 输出唯一 SRT/JSON；禁止复制后再手工维护第二套竖版字幕。
7. cue 内部需要逗号等标点时可以保留；切分出的每个 cue 结尾必须删除逗号、句号、问号、感叹号、分号、冒号、引号、括号、破折号、省略号等标点。

## 一致性检查

自动检查：

- cue 时间单调且无负时长；
- 同句 cue 拼接文字与 `displayText` 一致；
- `displayText` 与 `spokenText` 在忽略允许的显示标点后逐字一致；
- 每个 `displayText` 和 cue 的最后一个字符都不是标点符号；
- 最后一条字幕覆盖完整句尾；
- 字幕时间不超过完整配音时长。

已有字幕驱动配音时，读取专门的字幕配音规范并先做 dry-run。新制作项目默认采用“规划目标时长 → 生成实际配音 → 锁定字幕时间线”的顺序。

## 输出

- 特殊词发音表和试听；
- 逐句音频、完整配音和配音报告；
- 唯一显示字幕 SRT/JSON；
- 字幕与旁白一致性报告。

## 通过条件

- 用户确认声音和特殊词；
- 配音无截断、错读和异常加速；
- 字幕拼接文字与朗读一致；
- 正式时间线来自实际音频。

通过后把状态更新为 `subtitle_timeline_locked`。
