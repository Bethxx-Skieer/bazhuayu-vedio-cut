## 适用范围

用于 Agent、RPA、SaaS 产品、数字员工、自动化流程和企业案例等“真实操作素材＋业务解说”视频。把不同项目统一为一条从业务素材到正式成片的生产链；具体项目只替换业务内容、素材、角色规则和视觉主题。

## 核心协调规则

1. 由 `tutorial-video-slicing-workflow` 担任唯一总控。其他视频、配音、字幕、组件、Remotion 和 FFmpeg 能力只执行明确的下游任务，不得各自改写叙事、样式或时间线。
2. 只保留一份最终旁白脚本和一份主时间线。字幕、配音、镜头、组件和横竖版全部从它们派生。
3. 先完成素材理解和业务脚本，再做音画方案；方案未锁定时不进入大量渲染。
4. 按完整自然句生成配音。显示字幕可以按自然语义拆分，不能按镜头或短语切碎语音。
5. 优先使用真实操作素材。没有素材但业务链必需的内容，使用统一文字或流程组件表达，不得因为缺少画面而删除。
6. 先制作前 `60秒` 音画预览，再输出跨章节关键帧；两项都通过后才渲染全片。
7. 组件、真实视频、图片和章节卡默认进入同一条 Remotion 主时间线统一渲染。组件预览是确认样式的审批物，不是默认生产中间片段。

## 一、能力输入

尽量收集四类信息；缺少逐句文字稿时，直接读取素材并整理，不要求用户先手工标完时间码。

### 1. 视频素材

- Agent 对话与任务状态；
- RPA 采集、查询或系统执行；
- 产品、SaaS 和业务系统操作；
- 数据结果、可视化报告与交付文件；
- 人工确认、审核或决策页面。

### 2. 素材对应的文字稿

优先接收每段素材的动作说明：

- 输入了什么；
- 谁执行了什么；
- 在哪个平台或系统执行；
- 返回了什么数据或结果；
- 对应哪个业务环节。

有逐句稿时直接建立对应关系；没有时，通过抽帧、播放、OCR 和上下文自行整理。

### 3. 业务参考资料

- 业务流程与 SOP；
- 产品文档和案例文章；
- 演示讲稿与销售材料；
- 角色分工和判断标准；
- 已确认的业务价值、效果与事实边界。

### 4. 成片目标

- 目标观众与使用场景；
- 总览版或详解版；
- 期望时长和节奏；
- 横版、3:4 或其他明确画幅；
- 品牌、配色、字体、Logo 和组件要求。

## 二、完整 SOP

### 阶段一：理解素材并建立证据库

先探测全部视频的时长、画幅、帧率和音轨，再按固定间隔与场景变化点抽帧。结合文字稿识别输入、执行、等待、返回数据、分析、报告、人工确认和任务完成等节点。

输出素材清单，直接填写真实文件路径和源时间码，不使用难以定位的临时代号：

| 素材文件 | 源时间码 | 主要内容 | 业务环节 | 可证明的信息 | 推荐使用区间 |
|---|---|---|---|---|---|

这一阶段形成三个明确判断：

- 当前有哪些真实画面；
- 哪些业务内容有真实证据支撑；
- 哪些必要内容需要用字幕、旁白或视觉组件补齐。

产出：

- 素材清单；
- 素材与文字稿对应表；
- 初步业务流程结构；
- 可用素材证据库。

### 阶段二：策划并锁定业务脚本

根据素材和参考资料，重新组织面向观众的旁白。脚本围绕四个问题推进：

1. 原来需要完成什么业务任务；
2. 现在这套系统如何工作；
3. Agent、RPA、系统和人分别承担什么；
4. 任务完成后出现什么直接业务结果。

遵守以下写作规则：

- 从用户视角和业务价值出发，先讲业务动作，再讲技术实现；
- 只保留理解流程所需的技术名词和 Skill 名称；
- 每句话表达一个完整意思，上下句保持明确的业务承接；
- 对关键任务写清“需求—执行—分析—结果”；
- 区分直接结果、业务判断和未经证实的最终效果；
- 结尾回到流程连续性、决策质量、效率或经验复用。

同一批素材可以形成两种脚本：

- **总览版**：讲清业务主线、关键分工和整体价值；
- **详解版**：展开关键任务的输入、平台动作、数据返回、分析和结果。

产出：确认后的唯一旁白脚本。脚本未确认时，不生成正式配音、字幕或成片。

### 阶段三：展开音画剪辑方案

脚本确认后，为每一句旁白建立完整映射：

| 输出时间 | 完整旁白 | 显示字幕 | 画面设计 | 原始素材与源时间码 | 组件 | 画面提示 |
|---|---|---|---|---|---|---|

同步设计四层内容。

#### 配音设计

- 锁定音色、语速、情绪和句间停顿；
- 为 AI、Agent、Skill、RPA、ROI 等术语建立独立 TTS 发音稿；
- 按完整自然句生成，不按镜头切碎；
- 用实际配音时长反推镜头时长和预计成片时长。

#### 字幕设计

- 显示内容与旁白语义一致；
- 长句按自然语义拆成单行显示字幕；
- 全片共用字号、位置、底板和安全区；
- 保持旁白、显示字幕和 TTS 发音稿的来源关系可追溯。

#### 真实画面设计

关键任务优先形成连续证据链：

```text
提出需求 → Agent 理解并调用能力 → RPA 或系统执行
→ 数据返回 → Agent 分析 → 输出报告或结果 → 人工确认（如有）
```

一条旁白涉及完整任务时，优先使用同一任务从输入到结果的连续素材。操作页面和报告页默认全屏或适当放大，保证标题、关键指标和结论可读。

#### 组件画面设计

仅在真实素材缺失、信息抽象或需要快速建立结构时使用组件。组件承担信息表达，不作为装饰。

优先复用：

- 开场业务流程；
- 章节过渡；
- 顶部说明标签；
- 人工确认；
- 多路径汇入与候选池；
- 分层验证与商品筛除；
- 供应、利润和商业判断；
- 视觉制作与系统上架；
- 停止、优化和扩展；
- 数据回写与流程循环；
- 人机分工、经验复用和结尾价值落版。

所有组件读取同一套颜色、字体、字号、卡片、间距和动画变量。不要在画面上显示“人物观点”“核心判断”等内部组件类型名称。

产出：

- 完整剪辑方案；
- 旁白时间线；
- 字幕时间线；
- 素材匹配表；
- 组件调用表；
- 预计成片时长。

### 阶段四：按固定顺序正式制作

#### 1. 生成完整配音

按完整句子逐句生成语音，得到真实声音时长。输出完整配音 WAV、整句配音时间线、TTS 发音稿和配音报告。

#### 2. 生成显示字幕

从同一份旁白时间线派生显示字幕。允许拆分显示，但文案来源和时间轴保持唯一。输出 SRT/JSON 和字幕布局报告。

#### 3. 剪辑真实素材

根据实际配音时长裁切素材、调整播放区间和速度，连续组织同一任务。全屏展示关键操作和报告，必要时放大界面重点，并使用统一顶部标签说明当前动作或结果。

#### 4. 补充统一组件

只调用已确认的组件体系补齐没有真实画面的必要业务信息。组件不得改变脚本含义，也不得引入第二套配色、卡片、标签或动画规则。

#### 统一代码渲染与合成原则

把每个镜头写入同一份主时间线数据，至少区分以下类型：

| 镜头类型 | 默认处理 |
|---|---|
| `component` | 用 React/Remotion 组件绘制文字、卡片、节点、箭头和动画 |
| `video` | 在当前镜头区间播放并裁切真实操作素材 |
| `image` | 展示截图、报告、数据表或其他静态证据 |
| `chapter-card` | 渲染章节过渡和结构提示 |

由同一个 Remotion Composition 按主时间线逐帧编排所有镜头，统一控制画幅、帧率、主题变量、动画节奏和转场。默认直接渲染一条完整画面母版，不先把每个组件导出成 MP4 再拼接，以减少中间文件，并避免比例、帧率、清晰度、转场和样式发生漂移。

单独导出的组件静帧或短视频只用于以下情况：

- 用户确认组件视觉和动画；
- 用户明确需要在剪映、Premiere 等外部工具继续手工编辑；
- 某个组件需要作为独立片段跨项目复用；
- 当前项目与目标项目的渲染环境无法共用同一条主时间线。

需要单独导出组件视频时，必须与主项目共用分辨率、帧率、SAR、颜色、字体和主题变量，并由主时间线重新装配。预览文件不得替代最终画面母版。

#### 5. 生成画面母版

从同一条 Remotion 主时间线渲染无字幕、无配音的画面母版，检查镜头连续性、素材清晰度、组件样式和画幅。

#### 6. 合入声音与字幕

按顺序生成：

1. 无字幕配音母版；
2. 字幕配音正式成片；
3. 用户需要时，从同一时间线派生3:4或其他平台版本。

### 阶段五：通过双重预览闸门

全片渲染前固定生成：

- **前 60 秒音画预览**：检查开场逻辑、语速、术语发音、字幕、真实素材和顶部标签；
- **跨章节关键帧**：覆盖后半程所有章节和组件类型，检查颜色、版式、字号、素材裁切和旧样式残留。

预览未通过时只修改受影响的脚本句、字幕 cue、单句音频、镜头或组件，再重做下游结果；不要默认从原始素材全部重来。

### 阶段六：完成成片质检

| 维度 | 检查内容 |
|---|---|
| 内容 | 业务逻辑、角色分工、事实边界和价值表达 |
| 声音 | 音色、语速、停顿、术语读法、整句连续性 |
| 字幕 | 与旁白一致、单行显示、无溢出、无遮挡 |
| 画面 | 素材清晰、任务连续、报告可读、组件统一、无黑边 |
| 技术 | 时长、分辨率、帧率、音量、完整解码和样式锁定 |

至少完整观看前 60 秒，并在每个章节抽查一条任务全链路和一种组件。完成自动解码、时长与锁定检查后再进入交付。

## 三、能力调用结构

| 模块 | 职责 |
|---|---|
| 素材理解器 | 读取视频和文字稿，建立素材证据库 |
| 业务脚本策划器 | 从业务价值出发生成唯一旁白脚本 |
| 音画方案设计器 | 建立配音、字幕、素材和组件时间线 |
| 声音生产器 | 生成术语正确、整句连续、逐句对齐的配音 |
| 视觉导演与渲染器 | 编排真实素材、调用统一组件并渲染画面 |
| 成片质检与交付器 | 检查锁定状态并整理最终文件 |

总控 Skill 负责阶段顺序、唯一内容源和质量闸门；底层能力不得同时担任导演。

## 四、具体项目内容包

每个项目只替换以下内容：

- 业务流程与核心任务；
- Agent、RPA、系统和人的角色规则；
- Agent 对话、RPA 执行、报告和系统页面等真实素材；
- 业务价值、结果证据和事实边界；
- 专属术语、发音和文案；
- 允许使用的组件、Logo 和视觉主题。

例如 AI 选品项目可以包含市场机会、经营验证、上架、测款和扩品；换成财务对账、跨境运营、社媒分析或客户服务时，只替换项目内容包，通用生产 SOP 保持不变。

## 五、最终交付物

```text
01_正式视频
    正式字幕成片
    无字幕配音母版
    无字幕无配音画面母版

02_脚本
    最终旁白脚本

03_字幕
    显示字幕
    整句旁白时间线

04_配音
    完整配音
    TTS发音稿

05_画面设计
    完整剪辑方案
    素材匹配表
    镜头时间线
    组件调用表
    样式规范

06_质检
    配音报告
    字幕报告
    画面报告
    成片检查报告

07_工程
    可继续修改和渲染的工程文件
```

最终主路径：

> 接收素材与文字稿 → 理解素材 → 提炼业务价值 → 输出并锁定脚本 → 展开音画方案 → 生成整句配音和显示字幕 → 匹配真实素材 → 用统一组件补齐 → 渲染母版 → 合成成片 → 质检交付

## 六、完成标准

- 业务逻辑准确，角色分工与素材事实一致；
- 旁白自然、紧凑，能够独立听懂；
- 显示字幕与旁白语义一致；
- 配音整句连续，无异常断气、截字和速度漂移；
- 真实素材优先，关键任务形成连续过程；
- 素材缺口由统一组件完整补齐；
- 组件、真实视频、图片和章节卡由同一条主时间线统一渲染；
- 全片视觉规范统一且可通过主题变量整体换色；
- 前 60 秒预览与跨章节关键帧均通过；
- 正式成片通过完整解码和锁定质检；
- 全部可复用文件进入最终交付目录。
