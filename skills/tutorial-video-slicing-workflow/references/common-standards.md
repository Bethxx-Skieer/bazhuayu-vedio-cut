# 通用标准：闸门、参数、排错与清单（子 Skill）

所有叙事模式在整片渲染与交付前共用本文件。模式专属规范见 [enterprise-business-demo-production.md](enterprise-business-demo-production.md)、[social-promo-effect-first.md](social-promo-effect-first.md) 等路由目标。

## 一、样式与声音锁定闸门（整片渲染前依次执行）

1. 用唯一 SRT 和 `scripts/burn_subtitles.py` 生成包含短、中、长字幕的前 60 秒预览。
2. 用 `scripts/subtitle_voiceover.py --dry-run` 验证时间轴，再按中文声音配置（`assets/voiceover-profile-zh-CN.json`，黎潋）逐句生成旁白。
3. 抽查前 60 秒：字幕为单行紧凑圆角灰黑底、原生白色粗体、无人工描边、宽度不超过约 83% 画面宽；核对中文字形与黎潋音色。
4. 整片生成后运行 `scripts/validate_render_lock.py`；返回非 `status: ok` 不得交付。

## 二、三条子流程图

### 产品演示增强（在叙事剪辑、字幕与配音全部锁定后）

禁止在仍会改动的时间线上凭感觉堆特效：

```text
锁定16:9剪辑、字幕、配音与增强事件
    → 逐帧确认关键动作：点击/输入/等待/阶段/结果/完成
    → 建立 enhancement-cues.json
        ├── 渲染透明视觉覆盖层
        └── 合成 enhancement-sfx.wav + QA JSON
    → 生成无字幕增强内容母版
        ├── 渲染16:9字幕布局
        └── 按framing-cues铺满3:4产品框并渲染竖版字幕
```

细则见 [product-demo-enhancement.md](product-demo-enhancement.md)。

### 字幕配音对齐（字幕时间表确认后、最终质检前插入）

```text
带时间码字幕 → 解析并校验cue(SRT/VTT/ASS/JSON)
→ 逐句调用TTS（黎潋配置/Voicebox适配器/用户确认的替代音色）
→ 时长适配（短句补静音；轻微超时加速；明显超时报错）
→ 按时间码拼接（输出独立WAV + JSON质检报告）
→ 合成回视频（替换原声或压低原声后混音）
```

不得把整篇纯文本配音冒充为已对齐音轨，不得默认截断超时句尾。细则见 [subtitle-voiceover.md](subtitle-voiceover.md)。

### 字幕单一时间源

横版使用 `assets/subtitle-style-1920x1080.json` + `scripts/subtitle_layout.py`；品牌化 3:4 版本根据同一份 SRT/JSON 在产品框外重新布局。禁止复制文案和时间轴形成第二套字幕。烧录报告必须记录样式 SHA-256、字体、颜色和布局状态。社媒说明字幕固定使用单行紧凑圆角容器、半透明中性灰黑底和原生白色粗体；禁止两行大段字幕、接近满宽的大背景板、直角框和人工白色描边增粗。

## 三、技术参数速查

### 编码参数

| 参数 | 16:9母版 | 3:4派生版 | 说明 |
|------|---------|---------|------|
| 编码器 | libx264 | libx264 | H.264最大兼容性 |
| CRF | 18 | 20 | 越低质量越高 |
| Preset | fast | fast | 平衡速度与压缩 |
| 帧率 | 30 | 30 | 统一帧率 |
| 音频 | AAC 256k | AAC 256k | 保持音轨同步 |
| 像素格式 | yuv420p | yuv420p | 最大兼容性 |
| SAR | 1:1 | 1:1 | 防止非方形像素导致比例漂移 |
| moov | +faststart | +faststart | 流式播放支持 |

### 分辨率

| 类型 | 分辨率 | 适用平台 |
|------|--------|---------|
| 横版母版 | 1920x1080 | 公众号/B站/YouTube/西瓜 |
| 小红书3:4 | 1080x1440 | 小红书 |
| 可选9:16 | 1080x1920 | 仅用户明确要求时从同一母版纯黑补边派生 |

### 3:4 冰蓝品牌画布参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 画布 | `1080×1440`, `SAR 1:1` | 冰蓝品牌渐变背景 |
| 标题区 | `x=60,y=86,w=960,h=320` | 第一行蓝底白字、第二行 `#3F3F3F`；字距 `0.02em/0.04em` |
| 产品框 | `x=48,y=457,w=984,h=672` | 白色产品证明卡 |
| 录屏视窗 | `x=56,y=465,w=968,h=656` | 默认 `fill`，等比裁切铺满 |
| 模块间距 | 标题→产品 `100px`；产品→字幕 `100px` | 上下外部可见留白均约 `135px` |
| 字幕区 | `x=60,y=1229,w=960,h=76` | 中性深灰字幕底，单行居中 |
| 取景 | `left/center/right/custom` | 逐镜头写入 `framing-cues.json` |
| 字幕处理 | 共用文案与时间码，竖版独立排版 | 产品框外、单行、自适应宽度、无句号 |

## 四、常见问题与排错

**Q1 中文 zip 文件名乱码**：Python `zipfile` 在 Windows 默认 cp437 解码，中文 zip 通常 GBK 编码。解决见 slicing-workflow-steps.md Step 1 三级 fallback 解码。

**Q2 ffmpeg 解析分辨率显示 0x1**：部分视频元数据异常，不影响播放与处理，可忽略；需精确分辨率时用 ffprobe 或截一帧检测。

**Q3 场景检测阈值怎么选**：0.3 只测大幅切换；**0.15 推荐用于板块标题卡/PPT 翻页**；0.05 逐镜头分析（数据量大）。

**Q4 3:4 版本是否需要重新排字幕**：需要重新渲染版式，但不重新写文案或标时间。横竖版共用同一份 SRT/JSON、配音和音效；竖版字幕放产品框外，按 3:4 规范使用适配手机阅读的字号与自适应宽度。禁止把已烧录的横版字幕缩进产品框。

**Q5 切割后音画不同步**：`-ss` 在 `-i` 之前是快速 seek（跳到最近关键帧），可能丢帧。需帧级精确时把 `-ss` 移到 `-i` 之后（慢速 seek）。

**Q6 大文件处理超时**：2GB+ 视频场景检测约 5–10 分钟，切割每段 30 秒–2 分钟，竖版转制 1–3 分钟/段，总计 15–30 分钟；设置充足超时或后台运行。

## 五、复刻执行检查清单

环境准备：
- [ ] Python 虚拟环境已创建，`imageio-ffmpeg` 已安装，ffmpeg 路径已获取
- [ ] 输出根目录已创建

Step 1–2 解压与探测：
- [ ] zip 已解压且中文文件名正确显示
- [ ] 视频时长/分辨率/帧率已获取
- [ ] 非 16:9 源已无拉伸标准化为 1920×1080、SAR 1:1
- [ ] 每 30 秒截图已生成

Step 3 内容分析：
- [ ] 场景检测已执行（阈值 0.15），关键时间点帧已提取
- [ ] 截图已逐帧阅读，板块边界已确认，SEGMENTS 时间码已填入

Step 4 板块切割：
- [ ] 4–6 个板块已切割，每个文件 >1MB，segments.json 已生成

Step 5 切片提取：
- [ ] SLICES 列表已按截图分析与选题矩阵填入
- [ ] 横版切片全部成功
- [ ] 3:4 切片全部由同一增强内容母版、字幕时间轴、音轨和事件表自动渲染
- [ ] `framing-cues.json` 已逐镜头确认，产品区铺满且保留关键内容
- [ ] slices.json 已生成

Step 6 成品输出与质检：
- [ ] 三级目录结构完整，切片成品说明.md 已生成，全部文件可正常播放
- [ ] 前 60 秒预览已检查：字幕单行、紧凑宽度、圆角灰黑底、原生粗体、无人工描边、字形与音色正确
- [ ] 字幕报告记录的样式 SHA-256 与唯一配置一致
- [ ] 配音报告记录的声音为黎潋，或有用户明确批准的替代音色
- [ ] `scripts/validate_render_lock.py` 返回 `status: ok`

## 六、变量替换表

| 占位符 | 说明 |
|--------|------|
| `{ZIP_FILE_PATH}` | 源 zip 文件完整路径 |
| `{WORKSPACE}` | 会话工作目录（临时处理用，含 .venv/raw_footage/screenshots） |
| `{VIDEO_FILENAME}` | 解压后的视频文件名 |
| `{OUTPUT_ROOT}` | 最终成品输出目录（交付给用户的目录） |
| `{DOWNLOAD_DIR}` | 批量处理时多期 zip 所在目录 |
| `{ffmpeg_path}` | 由 `imageio_ffmpeg.get_ffmpeg_exe()` 获取，勿硬编码 |
