# 阶段四：画面匹配与动画补齐

## 目标

为正式配音时间线中的每个自然句设计可理解、可证明、节奏合适的画面。真实素材负责证据，组件负责结构和抽象信息，不把组件当装饰。

## 镜头映射

每个镜头至少保存：

| 字段 | 含义 |
|---|---|
| `shotId` | 稳定唯一 ID |
| `startSec/endSec` | 输出时间 |
| `sentenceIds` | 对应自然句 |
| `kind` | `video/image/component/chapter-card` |
| `assetId` | 真实素材 ID；组件可为空 |
| `sourceInSec/sourceOutSec` | 源区间 |
| `playbackRate` | 播放速度 |
| `semanticType` | 输入、执行、结果、报告、动画等 |
| `cropPolicy` | 语义化裁剪策略 |
| `statusLabel/mainTitle` | 状态小标题与具体主标题 |

## 画面选择顺序

1. 有真实操作、数据或报告证据时优先使用真实素材。
2. 一句话描述完整任务时，优先展示同一任务的输入或调用和稳定结果。
3. 执行中间过程有可观察变化时压缩展示；纯等待直接删除。
4. 抽象能力、数据字段、流程复用、角色关系和业务价值使用统一动画组件。
5. 没有真实素材但业务链必需时使用组件补齐，不删除旁白。
6. 报告索引已经能够说明多类交付时，不额外闪现大量详情和原始证据制造混乱。

## 时间与信息密度

- 镜头时长以旁白和可读性为准，不机械套用固定秒数。
- 输入画面至少让观众看清任务对象和发送动作；结果画面至少让观众识别报告或数据形态。
- 多个相似场景可以统一采用“短调用＋较长结果”的节奏模板，但每类必须有明确差异。
- 画面来不及看清时，优先减少层级、冻结关键结果或删掉无用过渡，不使用高频闪屏。
- 需要加速时优先去掉等待和滚动，再对保留片段整体加速。

## 视觉层级

统一使用：

- 品牌标识：固定小字号品牌信息；
- 状态标题：如“调用技能”“分析结果”，采用次级层级；
- 主标题：具体技能或具体结果，采用最大层级；
- 顶部标签：说明当前动作或结果；
- 字幕卡：只承载实际旁白文字。

动画、录屏覆盖文字和平台版本必须读取同一字体与设计令牌。首次建项目时可以从 `assets/design-tokens.template.json` 派生项目配置。复用既有组件时直接引用原实现，不根据截图另画相似版本。

## 任务连续性检查

逐个关键任务检查：

```text
观众是否看见输入或调用？
→ 是否看见稳定结果？
→ 旁白是否只描述画面能够证明的内容？
```

不能闭环时，选择补素材、补组件或修改旁白，不用无关画面填充。

## 输出

- 唯一镜头时间线；
- 素材与旁白映射表；
- 组件调用表；
- 状态标题和主标题表；
- 缺口与待确认项。

## 通过条件

- 每个自然句都有画面；
- 关键任务有输入和稳定结果；
- 没有误用加载、失败或不完整页面；
- 组件风格统一且没有引入第二套时间线。

通过后把状态更新为 `visual_timeline_locked`。
