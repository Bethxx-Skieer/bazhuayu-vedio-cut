# 运行环境、确定性脚本与下游 Skill 路由

## 四层能力模型

不要把以下四层混为一谈：

| 层级 | 作用 | 能否单独保证复现 |
|---|---|---|
| 底层工具 | 真正执行任务的程序、库或 API，例如 FFmpeg、Remotion、TTS 服务和 MoviePy | 不能；版本、参数和环境不同会产生差异 |
| 已验证脚本或适配器 | 固定输入、输出、参数、错误处理和报告，调用底层工具完成一个明确动作 | 是标准生产路径的核心 |
| 独立 Skill | 告诉智能体何时使用工具、怎样设计或诊断，以及有哪些专业边界 | 不能；它是知识和路由，不是可执行程序 |
| 总控 Skill | 管理阶段、单一事实源、审批和质检，选择已经批准的执行路径 | 不能替代底层工具和脚本 |

官方 Skill 可以包含说明、参考资料、资产和可选脚本；需要确定性行为或外部工具时，应把实现固化为脚本。复制 Skill 只能复制工作方法，不能自动复制 FFmpeg 二进制、Node/Python 包、字体、浏览器或 TTS 服务。

## 标准执行策略

采用“已验证脚本优先，Skill 负责维护和异常”的规则：

1. 常规生产只运行版本受控、通过测试的脚本、TTS 适配器和 Remotion 工程，不让智能体临时拼接命令代替标准实现。
2. 只有新增能力、修改渲染实现、接入新提供方或现有脚本无法解释的异常，才读取对应独立 Skill。
3. 新能力首次可以在 Skill 指导下实现；验证通过后必须收敛为脚本、配置、锁文件和测试样例，下一次直接复用。
4. 不允许在 FFmpeg、Remotion、MoviePy 之间静默切换，也不允许 TTS 静默更换提供方、模型、音色或参数。
5. 每次执行都把脚本版本、底层工具版本、关键参数、输入输出哈希和验证结果写入报告。

## 阶段路由

| 阶段 | 标准生产路径 | 何时读取独立 Skill | 禁止越界 |
|---|---|---|---|
| 素材探测、抽帧、标准化、精确裁切 | 已验证媒体脚本调用锁定版本的 FFmpeg/FFprobe | 新格式、复杂音轨、编码或同步异常时读取 `ffmpeg` | 不改脚本语义、字幕和镜头时间线 |
| 试听与正式配音 | 已验证 TTS 适配器按完整自然句调用锁定的提供方、模型、音色和参数 | 接入或更换提供方、修改重试和缓存策略时读取 `generate-voiceover` 或提供方 Skill | 不按短 cue 切碎新制作旁白，不静默回退 |
| 字幕 cue、布局和烧录 | 本 Skill 的时间线、布局和烧录脚本 | 正常路径不读额外 Skill | 不维护第二份字幕，不允许 cue 句末标点 |
| 组件、动画、镜头编排和横竖版 | 锁定依赖的 Remotion 模板或项目读取唯一内容时间线 | 新建或修改渲染器时读取 `remotion` 与 `remotion-best-practices` | 不重新决定旁白、字幕时间和业务事实 |
| 音频归一、混音、封装、平台编码和解码验证 | 已验证后处理脚本调用锁定版本的 FFmpeg | 新滤镜或兼容问题时读取 `ffmpeg` | 不改变内容时长，除非项目清单明确批准 |
| 特殊 Python 合成 | 默认关闭；明确选择后运行固定版本的 MoviePy 脚本 | Remotion 确实不适合且用户批准 Python 路径时读取 `moviepy` | 不与 Remotion 同时维护两套正式工程 |

## 四类工具的使用边界

### FFmpeg

负责媒体探测、抽帧、转码、裁切、调速、音频归一、混音、封装、压缩和完整解码验证。标准任务必须由脚本传入明确参数；`ffmpeg` Skill 仅用于新增处理策略或诊断异常。

查找顺序：项目运行时配置指定路径 → 固定共享运行时 → 项目依赖中经过验证的二进制 → 系统 PATH。选定后记录版本和文件哈希。不要因为 PATH 中没有命令就认定机器没有可用 FFmpeg。

### Remotion

是本工作流默认的正式画面编排器，负责组件、动画、镜头、字幕组件和多画幅布局。标准发行物必须包含真实 Remotion 工程模板、依赖锁文件、固定帧率、字体文件或字体哈希、浏览器版本和渲染入口；单独安装 `remotion` Skill 并不会生成同一工程。

`remotion` 与 `remotion-best-practices` 用于编写、审阅和维护工程。正式项目执行时直接运行已验证的渲染入口，只读取项目清单中的唯一内容时间线。

### TTS

TTS 是外部或本地声音引擎，标准接口至少固定：提供方、模型、音色 ID、语言、语速、稳定度或情绪参数、采样率、文本预处理版本和特殊词词典。先生成代表性试听；确认后按完整自然句生成并返回真实音频时长。

`generate-voiceover` 或提供方 Skill 负责接入和专业策略，不是声音引擎本身。`scripts/subtitle_voiceover.py` 只用于“已有字幕驱动配音”的兼容分支；其默认 macOS `say` 后端不是跨平台正式方案，也不得用于新制作项目的完整自然句主路径。

云端 TTS 可能随服务更新产生细微变化。要求完全复现已批准成片时，必须缓存并随项目保存逐句原始音频及其哈希；重新请求相同文本不视为完全相同的声音输入。

### MoviePy

MoviePy 只用于明确批准的短片、AI 视频文字覆盖或一次性 Python 合成。正常教程、企业演示和横竖版项目以 Remotion 为唯一正式画面工程，MoviePy 不作为自动故障回退。若启用，必须锁定 Python、MoviePy、Pillow、底层 FFmpeg 和字体，并提供单一构建脚本与测试样例。

## 跨系统复现等级

| 等级 | 定义 | 适用保证 |
|---|---|---|
| `native-equivalent` | Windows、macOS、Linux 使用各自锁定运行时 | 保证内容、布局、时长和视觉在容差内一致，不承诺文件逐字节相同 |
| `container-deterministic` | 所有电脑调用同一 Linux 容器、浏览器、字体和软件编码链 | 才适合追求高度确定的同帧输出；最终文件哈希仍需实测确认 |

要接近“不同电脑完美复现”，发行包至少同时包含：

- 本总控 Skill 与所需独立 Skill 声明；
- FFmpeg、Node、Python、Chromium 和字体的锁定版本或同一容器镜像摘要；
- Remotion 正式工程、依赖锁文件和确定性渲染入口；
- FFmpeg、TTS 和可选 MoviePy 的已验证适配脚本；
- 项目清单、运行时配置、设计 token、发音词典和平台配置；
- 缓存的已批准 TTS 逐句音频及哈希；
- 黄金测试素材、参考帧、参考时长、音频指标和允许误差；
- 安装前检查、完整渲染测试和交付验证。

只分发 Skill 文件夹而没有上述运行时与测试层，只能称为“可复用工作流”，不能称为“跨系统可复现剪辑标准”。

## 启动检查与失败处理

1. 读取项目清单中的执行策略和运行时要求。
2. 验证脚本、锁文件、可执行程序、包版本、字体、浏览器、声音适配器和黄金测试是否存在。
3. 能复用匹配运行时则记录真实路径与哈希；缺失时停止并说明安装项，不静默使用系统其他版本。
4. 标准脚本未覆盖新情况时，先返回错误；在对应 Skill 指导下扩展并测试后，再纳入标准路径。
5. TTS 不可用时停止正式配音；Remotion 渲染失败时修复同一工程；MoviePy 不得自动接管。

## 宿主兼容性（WorkBuddy / 千问办公）

本 Skill 同一份内容在两种宿主均可加载，差异只在安装目录与接口元数据：

| 宿主 | 技能安装目录 | 加载的接口元数据 |
|---|---|---|
| WorkBuddy（Codex） | `~/.codex/skills/tutorial-video-slicing-workflow/`；Windows 为 `%USERPROFILE%\.codex\skills\` | frontmatter 的 `name`＋`description` 与 `agents/openai.yaml` |
| 千问办公（QwenWork） | `~/.qwenworkcn/skills/tutorial-video-slicing-workflow/`；Windows 为 `%USERPROFILE%\.qwenworkcn\skills\` | 完整双语 frontmatter（`description_zh`、`argument-hint*` 等）与 `.skill-metadata.yaml` |

- 两端共享同一份 `SKILL.md`、`references/`、`scripts/` 和 `assets/`；对方不认识的字段会被忽略，不得为某一端复制出第二份技能内容或另一套规范。
- 切换宿主不算环境变更：FFmpeg、Node、Python 和字体仍按上文查找顺序复用已锁定的共享运行时与依赖，不因更换对话或软件而重装依赖、重新调用 TTS 或重渲染已批准产物。
- 更新时以版本仓库中的技能目录为唯一来源，拷贝到各宿主目录后重启生效。
