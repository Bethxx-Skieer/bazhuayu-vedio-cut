# 阶段六：预览、质检与交付

## 目标

在昂贵的全片渲染前发现声音、字幕、素材状态、裁剪和视觉问题；正式成片完成后同时验证内容与技术质量。

## 双重预览闸门

全片渲染前固定生成：

1. **前60秒音画预览**：检查开场逻辑、语速、特殊词、字幕、真实素材、组件和标题标签。
2. **跨章节关键帧**：覆盖后半程所有章节、镜头语义、组件类型和平台布局。

关键帧至少覆盖：

- 特殊词所在句；
- 最长字幕；
- 输入或发送任务；
- 稳定结果；
- 单栏结果与双栏报告；
- 报告索引；
- 连接或安装成功状态；
- 动画组件；
- 结尾；
- 横版与竖版代表镜头对照。

预览未通过时只修改受影响的自然句、单句音频、字幕 cue、镜头、裁剪或组件，再重新生成相应下游产物。

## 质检维度

| 维度 | 检查内容 |
|---|---|
| 内容 | 业务逻辑、事实边界、角色分工、输入和结果 |
| 声音 | 音色、语速、停顿、特殊词、句尾和音量 |
| 字幕 | 与朗读一致、时间正确、单行或合规换屏、无遮挡 |
| 画面 | 稳定素材、任务闭环、报告可读、组件统一、无黑帧 |
| 多画幅 | 共用时间线、裁剪合理、标题层级和安全区一致 |
| 技术 | 时长、分辨率、帧率、SAR、编码、音轨和完整解码 |
| 工程 | 版本、运行时、资产路径、项目清单和增量修改能力 |

## 自动检查顺序

1. 运行 `scripts/validate_project_manifest.py project-manifest.json`；
2. 使用字幕布局和烧录脚本生成报告；
3. 使用媒体工具验证每个正式成片的时长、流信息和完整解码；
4. 运行 `scripts/validate_render_lock.py` 检查声音和字幕样式锁定；
5. 检查平台版本只保存布局覆盖项；
6. 检查输出文件与项目清单中的版本和路径一致。

过程检查报告保存到内部工作目录 `work/qa/`。任何 `error` 都阻止交付；`warning` 必须人工确认并记录理由。最终采用的质检结论、通过报告和必要证据复制到 `delivery/06_质检/`；临时检查文件不进入正式交付。

## 正式渲染与交付

预览通过后按顺序生成：

1. 无字幕、无配音的画面母版；
2. 无字幕配音版；
3. 正式字幕成片；
4. 所需平台适配版本；
5. 内部保存对应的字幕、配音、镜头和质检资料。

前两项和各类预览属于内部生产产物，不进入正式交付。默认交付完整但干净的最终版本：

```text
delivery/
├── 01_正式视频/
├── 02_脚本/
├── 03_字幕/
├── 04_配音/
├── 05_画面设计/
├── 06_质检/
└── 07_工程/
```

七个目录都只放与当前最终成片对应的正式版本。不要把审批预览、无字幕版、无配音母版、旧版本、失败渲染、临时音频、过程报告、缓存或历史工程复制进 `delivery/`。

`07_工程/` 只包含复现最终成片所需的干净工程：源代码、配置、锁定文件、必要资产和说明。不要包含 `node_modules/`、虚拟环境、构建产物、缓存、临时文件或历史版本。`work/` 与 `archive/` 始终位于 `delivery/` 之外。

## 通过条件

- 前60秒和跨章节关键帧已通过；
- 字幕与配音一致；
- 没有加载骨架、错误页面和异常裁剪；
- 横竖版来自同一内容时间线；
- 成片完整解码；
- 项目清单和锁定校验均为 `ok`；
- 七个正式交付目录齐全，且都只包含当前最终版本；
- 横版与竖版成片、脚本、字幕、配音、画面设计、质检和工程互相对应；
- `work/`、`archive/`、预览、失败渲染、缓存和历史版本均不进入正式交付。

自动与人工检查全部通过后依次更新为 `qa_passed` 和 `delivered`。
