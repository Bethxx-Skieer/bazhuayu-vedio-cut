# 阶段一：素材接收与证据库

## 目标

在写脚本前弄清现有事实、可用画面、素材缺口和成片要求。不要要求用户预先手工标完时间码；能够通过探测、抽帧、OCR、播放和上下文判断时自行完成。

## 输入

- 宣传文章、产品资料、业务 SOP 和已确认事实；
- 原始录屏、切片、截图、报告、数据表和交付文件；
- 品牌字体、颜色、Logo、参考视频和既有组件；
- 目标受众、平台、画幅、时长、节奏和交付范围。

## 执行要求

1. 保持原始素材只读，在项目目录建立工作副本或路径引用。
2. 探测视频时长、分辨率、帧率、SAR、音轨和编码；记录实际路径，不使用无法定位的临时代号。
3. 按固定间隔与场景变化点抽帧；长素材先粗扫，再在候选片段附近加密检查。
4. 标记每段画面的语义和状态：
   - `input`：输入关键词、ASIN、指令或参数；
   - `execution`：系统或 Agent 正在执行；
   - `loading`：骨架、等待或未稳定页面；
   - `success`：安装、连接、任务等成功状态；
   - `result`：数据、结论、报告或交付物；
   - `report-index`：多类报告索引；
   - `report-detail`：单个报告详情；
   - `error`：错误尝试或失败状态。
5. 为每个候选片段记录源入点、源出点、可证明事实、关键内容位置、可否加速、推荐裁剪语义和稳定性。
6. 默认排除 `loading`、`error`、鼠标游移、重复滚动、无变化页面和不完整结果；确需表现执行过程时只保留发生变化的节点。
7. 识别关键任务是否具备“输入或调用 → 稳定结果”。缺一端时记录为画面缺口，不要在脚本中假设已经有完整证据。
8. 检查旧组件和品牌样式能否复用；记录其真实实现文件，不根据截图重新临摹。

## 素材证据表

每条素材至少保存：

| 字段 | 含义 |
|---|---|
| `assetId` | 稳定唯一 ID |
| `path` | 真实绝对路径或项目相对路径 |
| `sourceInSec/sourceOutSec` | 推荐源时间区间 |
| `semanticType` | 输入、执行、成功、结果、报告等 |
| `visualState` | `transitional/stable/success/error` |
| `evidence` | 可证明的业务事实 |
| `keyRegion` | 关键内容所在区域 |
| `cropPolicy` | `center/result-side/full/custom` |
| `speedRange` | 可接受的播放速度范围 |
| `notes` | 风险、模糊点和替代方案 |

## 默认工具

- 使用 FFmpeg 或等价媒体工具完成探测、抽帧和标准化；
- 使用图片查看、OCR 和人工视觉判断确认页面状态；
- 工具只提供证据，不得自行改写业务脚本。

## 输出

- `material-evidence.json` 或等价结构化证据表；
- 素材清单与关键帧；
- 可证明事实清单；
- 缺失画面与动画补齐清单；
- 目标画幅、时长和品牌要求。

## 通过条件

- 所有结论都能追溯到资料或明确标记为待确认；
- 关键素材有稳定源时间码和状态；
- 已区分加载、成功和结果；
- 已明确哪些句子可以使用真实素材、哪些需要动画。

通过后把项目状态更新为 `evidence_ready`。
