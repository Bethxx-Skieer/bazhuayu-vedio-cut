# 生产踩坑清单（实测复现的失败模式与解法）

## 本文定位

阶段 01–07 与各模式文档规定"应该怎么做"；本文只记录 **2026 年 9 月批次实际踩到、且已定位根因的失败模式**，按"现象 → 根因 → 做法"组织，供诊断时快速比对。本文不替代阶段规范，与规范冲突时以规范为准。

主要面向 Windows + imageio-ffmpeg + edge-tts 链路；第 7、8 节对 `interview-video-editing` 同样适用。

涉及项目：桑葚 ASIN 监控系列（横竖版）、三大异常篇、子视频2 排名监控、千问 AI 大赛两支参赛片、TEMU 对账横转竖、天猫零售对账客户案例片。

## 1. 素材与时间码：先核实，再当约束用

这是本批次**造成返工最多**的一类问题。

| 现象 | 根因 | 做法 |
|---|---|---|
| 念"伯俊ERP"画面却亮着"支付宝账单下载" | 脚本/执行稿里标的 `1–3 / 3–6 / 6–8 / 8–9s` 是估值，实测该素材四张卡高亮窗口为 `3.2–6.0 / 8.2–11.5 / 13.2–16.0 / 18.8s+`，整体晚 2–10 秒 | 脚本给的一切时间点视为**待验证输入**。取帧前按 0.5s 步进扫素材，程序化定位状态变化（如按卡片行统计蓝色描边像素密度），拿到实测窗口再填时间轴 |
| 定格框选落在空白表格上 | 名义时间点那一帧正好处于滚动中，内容不可读 | 定格帧必须挑"目标内容完整可见"的那一帧，不取名义时间点。用户口述"第 4 秒那一帧"实测该画面在 1.6s、4s 已滚过头，按内容取帧并说明偏差 |
| 入出点落在素材之外 | 脚本写"14–16s"，素材实际 14.82s | 所有素材先批量探测真实时长入库，引用超出长度的区间时当面向用户确认改点 |
| 角标写了画面里没有的结论 | 源里单元格文字本身是糊的，"处理完成"读不出来 | **画面读不出的结论不写进角标**。改为只框清晰可辨的表头，文案只陈述看得见的部分 |
| 二次叠加红框与素材自带标注打架 | 录屏里录制者已烧了红字标注 | 检查源是否已烧字幕/标注；已烧的素材上叠加改用另一色系（黄色框），静态截图仍用红框 |
| "全文件都有差异" | Windows 克隆时 CRLF/LF 转换 | 比对加 `--ignore-cr-at-eol`，别按表面差异判定内容变更 |

补充：竖版没有工程时只能从成片派生，逆向标定顺序为「场景边界 → 字幕卡宽度变化定位 cue 切换（卡是连续显示的，亮度法只能得到 14 段而非 44 条）→ 语音停顿分段定句（句间 0.55s 明显大于句内间隔）」。源为 720p 时缩到 1080 宽仅缩小 16%，烧录字幕仍可读，就不要重打字幕。

## 2. 音画同步与时间轴

| 现象 | 根因 | 做法 |
|---|---|---|
| 成片比配音短约 2–3s，后半段越播越靠前 | 镜头只覆盖语音时长，**句间停顿没有画面**，逐句累积 | 每句末尾镜头冻结补齐到下一句 `startSec`，再 concat。对齐 pass 必须显式跑，别指望渲染器顺手做 |
| 累计漂移 7.7s 却查不到单点原因 | 逐镜头误差各 0.1s 级，叠加后放大 | 出现漂移先分别求和画面轨与音轨时长，再逐镜头比对目标/实际，不要直接怀疑编码器 |
| `00:02:46.20` 被当成 48.20s，误判"文件被截断"并重做了三轮 | 时长解析函数忘乘 3600 | 解析时间码统一用一个函数并加单测；判断截断要看**帧数与末帧 PTS**，不是容器头字段 |
| 容器头时长与实际内容不一致 | muxer 写入的 duration 字段错误，流本身完好（4987 帧 = 166.23s） | 先 `ffmpeg -v error -i f -map 0:v -c copy -f null -` 配 showinfo 数帧确认内容，再决定是否需要重建 header |
| 倍速超限（要求 ≤4x 却算出 5.28x） | 先拍脑袋填入出点再算速度 | **由目标时长反推入出点**：`sourceSpan = targetDur × speed`，取 span 时同时校验 speed 在闸门区间内 |
| 字幕双层重叠 | 每条 cue 显示窗口首尾各外扩 0.05s，相邻 cue 有 0.1s 同显 | cue 窗口精确按起止时间给，不做外扩；交付前逐条核对相邻窗口 |
| 念到"透明盒"却框着布立方 | 镜头边界与字幕边界不同源 | 镜头边界直接对齐字幕 cue 起止，做到"念到哪、等到哪、框到哪" |

## 3. 配音与发音

| 现象 | 根因 | 做法 |
|---|---|---|
| ASIN 读成字母串、"冗余行"读成 háng | TTS 按字面读 | **替换只在 TTS 文本侧，字幕与画面保持原文**：ASIN→诶森、VOC→V O C（逐字母）、冗余行→冗余形 |
| 需要第三声的 "sěn" 读不出来 | 普通话不存在该音节，近似字诱导全部失败（诶伞/诶散韵母偏 an） | 用 pyworld 只改目标音节基频（实测 247→140→206Hz）。定位必须先按非周期性 AP 分段——词级时间戳会把"诶森"当一个词返回，整词压调会连"诶"一起改错；再加基频下限（女声韵母 >150Hz）过滤，否则会选中辅音的预浊化段 |
| 定点改一句配音后音色语速突兀 | 不知道原片实际语速 | **反标定**：用原句文本在同一音色下生成，比对时长与中位基频，推出原片语速（实测某成片为 +20%，时长偏差仅 1.3%），再按该参数生成新句 |
| 改文案后重跑配音，拿到的还是旧音频 | TTS 缓存键只带语速不带文本 | 缓存键必须含**文本哈希 + 语速 + 音色** |
| 长句硬切在词中间（"探测各 / 点一遍"）、`Agent` 被切成 `A / gent` | 拆分链只放了半角 `;:`，全角 `：；` 未作拆分点；英文 token 未保护 | 按 `。！？` → `；：` → `，` → `、` 四级拆分，拆分链必须含全角标点，英文 token 整体不切 |
| 成片超出平台时长上限 | 脚本按估的字数/语速规划，实际旁白更长 | 正式排时间轴前**先出真实语音时长**再对脚本规划，超槽位或超上限（如 787 字 @4.2 字/秒 = 187s > 3:00）必须当面确认取舍，不要静默压缩 |

## 4. FFmpeg 与滤镜硬限制

| 现象 | 根因 | 做法 |
|---|---|---|
| `Cannot allocate memory` | 44 路 overlay 字幕链、12 路 xfade 单条滤镜图都触发过 | 字幕**按镜头分组叠**（每镜头只叠自己的 2–4 条）；xfade 改**滚动两两叠化**（每次只合一个段，滤镜图恒定两路输入）。另注意给全画布 PNG 会爆缓冲，按卡片尺寸生成小图再定位 |
| 字幕窗口不生效、约 60s 后字幕全部消失 | 单帧 `-i` 图片输入在显示窗口开始前就被消费掉 | 用 `movie=` 源 + `eof_action=repeat`。但部分 build 不接受 `eof_action`（`No option name near 'repeat'`）；配合 `-loop 1` 时 PNG 本就是无限流，去掉该选项即可 |
| `No such filter: '0.0'` | `between(t,0.0,3.314)` 里的逗号被当作滤镜链分隔符 | 滤镜表达式内的逗号**必须转义** |
| 滤镜链无帧输出、组合命令静默失败 | `scale=1080:945` 高度为奇数，yuv420p 要求偶数 | scale/crop 尺寸一律取偶数。组合失败时逐级隔离测试（先单独 crop、再 +setpts、再 +scale） |
| `paste` 参数报错 | 坐标传了 float | 传给 `paste`/`overlay` 的坐标一律 `int()` |
| 竖版时长比目标短约 0.07s/镜头累积 | `int()` 截断帧数 | 用 `round()` 并按目标时长校验每镜头帧数 |
| PATH 里没有 ffprobe 就认为没有 FFmpeg | imageio-ffmpeg 只分发 ffmpeg 二进制 | 探测改解析 `ffmpeg -i` 的 stderr；查找顺序遵循 `runtime-and-tool-routing.md` |
| 拼接错乱 / 参数不一致 | 一次性 filter concat 输入过多 | 用 concat demuxer（同参数流拷贝） |
| 找不到字体、路径解析失败 | 字体名传系统字体名；盘符冒号未转义 | 字体传绝对路径；`movie=` 内路径转义为 `C\:` |
| 原地覆盖同一文件失败 | ffmpeg 不能读写同一路径 | 输出换名或换目录 |

## 5. Windows 与脚本工程习惯

| 现象 | 根因 | 做法 |
|---|---|---|
| **补丁静默失败但后续命令照样执行**（以为改了，实际渲染用的是旧文案） | bash heredoc 里的中文与反斜杠被转义吃掉；断言抛错，但命令用换行而非 `&&` 串联 | 含中文/反斜杠的脚本**一律用 Write/Edit 落 `.py` 再执行**；命令串联用 `&&`；改完必须 `grep` 回验关键字符串真的落盘 |
| 控制台输出中文乱码/报错 | GBK 代码页 | 不 print 中文到 stdout，结果写 UTF-8 文件再读 |
| shell 直接访问 `\\192.168.0.240\...` 被拦 | 共享路径访问限制 | UNC 路径只在 Python 里访问（445 端口通、路径可读写） |
| 无 BOM 的 UTF-8 PowerShell 脚本被当 GBK 解析 | 编码探测 | 跨平台批处理优先用 Python 脚本文件 |

## 6. 缓存与增量重渲染

本批次两次"改了没生效"都出在这里，且**光看代码查不出来**。

- **缓存判断只比时长 → 静默复用旧版式产物**：改了视窗几何后 `canvas.png` 是新的，但旧几何产出的 38 个镜头时长未变，被判定有效直接复用，新画布叠旧内容凭空长出 x56–134 的暗带。
- **RESUME 见文件存在即跳过**：时间轴已改对，但 `tmp/S6a.mp4` 等是上一轮旧窗口生成的，于是新时间轴配旧素材，画面照旧错。

做法：

1. 凡会影响**画面**的输入都进指纹：版式几何参数 + 画布/组件 PNG 的文件哈希 + 镜头入出点 + 素材源路径，写成 `.geom` 文件；指纹变化即作废全部派生产物。
2. 重跑前先数一遍目标镜头的产物时间戳是否新于时间轴文件，而不是只看存在与否。
3. 中间产物文件名有优先级（`_final` / `_al` / `_ov`）时，多轮迭代容易取到旧产物——本轮重渲染前清掉受影响镜头的中间件。
4. 渲染器里"输出与输入同名则跳过复制"要真的比较解析后的路径；分支合成后若还有公用合成块，必须加跳过守卫，否则同一镜头被覆盖两次。

## 7. 横竖版与版式

| 现象 | 根因 | 做法 |
|---|---|---|
| 竖版设计卡上下露白边 | 卡片按 contain 放进白色产品框 | 先用卡片自身的底色铺满整个视窗，再叠卡片 |
| 三联图在竖版里左右面板被切 | 横排拼图硬按 fill 塞进 3:4 必然丢两侧 | 竖版按"一个镜头只点名一个系统"重排成单系统大图；品牌墙改纵排。拼图类不适用 fill 规范，需在交付说明里注明理由 |
| "稍微右移一点"结果露出整条素材留边 | 居中裁切窗口本来就正好卡在素材留边内侧（留边宽 160、裁切起点 164），往任一侧挪都会把留边拉进画面 | 先量留边宽度再判断。此类问题的解法是**取消偏移**，不是继续调像素数值 |
| 段落标签在浅色页面看不见 | 白字描边被浅底吞掉 | 状态标签用实心蓝底白字胶囊（实测 26px 字 / 54px 高），浅页深页都可读，并缩到不压表头 |
| 非 16:9 源变形 | 直接拉伸 1988×1240 | `crop` 去掉窗口标题栏与底部输入框凑成 16:9 再等比缩放，画面满幅且字更大，无黑边无变形 |
| 平台审核不过 | 结尾卡预留了二维码留白框 | 去掉二维码位，改品牌贴片 + 主张 + 领取引导，全部内容收在字幕安全线以上 |

## 8. 无工程时对成片定点替换

只有成片、找不到工程时的可行路径（本批次用于横版改一句旁白）：

1. 先备份原片，并在交付说明里写明"该文件不是本会话工程产出、找不到工程"。
2. 精测目标句：语音窗口用能量分段，字幕窗口用卡宽/亮度变化，取**字幕已消失、下句未出现**的时间隙作切点。
3. 用原句文本反标定原片语速与音色参数，再按该参数生成新句。
4. 新句更长时在切点插入**等长冻结帧 + 等长静音**，使后续画面、语音、字幕整体顺延；逐帧抽检验证顺延量一致、无漂移。
5. 重打字幕要复用原卡几何与配色（实测某成片卡底 `#47494E`、文字 `#E8E8E9`、圆角约 14），新卡更宽以完整覆盖原卡。
6. 重编码会让体积大幅下降（15Mbps → CRF17 约 2.6Mbps，298MB → 55MB）。投放渠道对码率有硬要求时必须提前说明并可用固定码率重导。

## 9. 协作与交付

- **只做点名改动，以最近交付版为基线。** 顺手重排版式会被打回（本批次开场被改成"竖版重排版"后要求回退）。回退时确认其余已确认项不动。
- **口径矛盾要显式消解，不能静默择一。** 例：卡片写"3 套"、旁白说"四套" → 加脚注说明"四套 = 3 套 RPA 取数对账 + 1 层 Agent 差异分析"；后续真正解法是四个流程彼此独立地重编号为流程一/二/三/四。
- 音画同步的自检是"按 cue 时间戳 + 逐帧抽检"，**不等于用耳朵过了一遍**；交付说明要写清验证方式，并请用户报具体秒数返修。
- 交付双落点：分发目录 + `outputs/`（present 工具读不到 D 盘，需复制）。
- 定点返修后回看受影响的下游产物清单：卡片变 → 补卡片镜头 + 重拼接 + 重出竖版；时间轴变 → 派生镜头全部作废（见第 6 节）。

## 10. 开工前 / 交付前检查清单

开工前：

- [ ] 全部素材真实时长、分辨率、帧率、有无音轨已探测入库（无 ffprobe 则解析 `ffmpeg -i`）
- [ ] 脚本内引用的每个时间点都用逐帧/0.5s 扫描核实过，高亮与定格窗口的实测值已回填
- [ ] 源素材是否已烧录字幕/标注已记录（决定叠加色）
- [ ] 旁白先出真实语音时长，与规划槽位、平台时长上限对过

交付前：

- [ ] 画面轨与音轨时长差 ≤ 0.3s（句间停顿已补齐）
- [ ] 逐条 cue 窗口无重叠；单行无溢出；相邻镜头无同显双层
- [ ] 倍速全部落在闸门区间（由目标时长反推所得）
- [ ] 完整解码通过；时长判断用帧数/末帧 PTS，不信容器头字段
- [ ] 本轮改动的影响范围已连带清除派生产物（`.geom` 指纹命中变化）
- [ ] 改过的脚本已 `grep` 回验落盘，不是"heredoc 以为改了"
