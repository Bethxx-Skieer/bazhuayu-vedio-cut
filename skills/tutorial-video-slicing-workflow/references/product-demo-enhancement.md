# 产品演示音效与视觉增强规范

本规范适用于产品、Agent、Skill、RPA、SaaS 和软件操作录屏。目标是让观众更容易看懂“做了什么、系统正在做什么、结果在哪里”，而不是把每个界面动作都做成娱乐化特效。

音效均为程序生成的短促合成声，不依赖外部版权素材。不要把 `audition.wav` 直接当作成片音轨；它只用于连续试听。

## 2. 事件识别与时间锚点

先对16:9母版建立 `enhancement-cues.json`。每个 cue 必须来自可观察的真实事件，至少记录：

- `time`：事件发生的秒数，精度不低于0.05秒；
- `event`：事件类型；
- `note`：画面证据或判断依据；
- 若需要覆盖默认声音，填写 `asset`；
- 若需要微调响度，填写 `gain_db`。

必须逐帧或以2–4帧步长检查关键动作。自动检测只能生成候选点，以下时间锚点必须人工或视觉模型复核：

| 事件 | 正确锚点 | 禁止做法 |
|---|---|---|
| 点击 | 鼠标按下或控件状态改变的瞬间 | 鼠标只是经过就加点击声 |
| 输入 | 字符真实出现的区间 | 文字已经输完仍继续播放键盘声 |
| 中文确认 | 最终转换后的中文稳定出现 | 在拼音输入阶段提前确认 |
| 任务开始 | 提交点击或首个“运行中”状态 | 只因配音说“开始”就伪造状态 |
| 执行阶段 | 对应状态可见，或画面无法显示时与配音关键词一致 | 画面已进入分析却仍标记清洗 |
| 结果出现 | 结果完整、稳定且可读之后 | 页面仍在加载就播放成功音 |
| 最终交付 | 承诺的主要成果同时可见之后 | 报告或数据包尚未出现就庆祝 |

## 3. 音效规则

### 3.1 强度预设

- `subtle`：全部音效降低4 dB，适合严肃教程、信息密集的公众号视频。
- `clear`：默认值。关键操作可明确听见，但不压过配音。
- `promo`：全部音效增加3 dB，仅用于节奏更强的社媒短片；仍受最终峰值上限约束。

用户未指定时使用 `clear`。不再默认把所有音效弱化到几乎听不见。

### 3.2 动作与声音

- 点击：仅给提交、搜索、安装、切换关键页等有叙事意义的真实点击加声。连续点击时轮换三种变体。
- 输入：按字符或字符组放置六种键盘音。高速输入时允许每2–3个字符一个音，避免形成机械连打。
- 输入完成：中文关键词稳定显示时使用 `ime_confirm`，不能比最后一个字符晚超过0.15秒。
- 等待：1秒以内不加声；1–3秒只保留任务开始声；超过3秒应优先剪短或加速。确需保留时，每1.5–2秒最多一个轻微进度脉冲，并在结果出现前0.35秒停止。
- 阶段：检索、采集、清洗、校验、分析、生成、导出使用各自音阶；仅在观众需要感知流程变化时使用，不要求每个阶段都有声。
- 中间结果：页面或卡片稳定后使用 `result_reveal`。
- 文件生成：文件名和文件图标出现后使用 `file_created`。
- 普通完成：使用 `task_complete`，一条短片通常不超过两次。
- 最终交付：使用 `final_delivery`，全片最多一次，是替代真人“wow”的默认满意反馈。
- 警告、失败、重试：只在原画面确有对应状态时使用，音色保持克制，不使用刺耳报警。
- 章节转场：章节卡稳定后轻微扫入，不在章节卡出现前抢声。

默认不使用真人“wow”、掌声或夸张欢呼。它们会改变产品演示的专业语气，也容易与配音冲突。背景音乐默认关闭；用户明确要求时再加。

## 4. 视觉增强规则

### 4.1 统一设计空间

所有绑定产品界面的视觉组件先在1920×1080坐标系中绘制。原素材非16:9时，先按画面内容裁切或重排为16:9，再叠加组件，形成不含平台字幕的增强内容母版。

16:9与3:4从同一增强内容母版和事件时间轴自动渲染。竖版按逐镜头 `framing-cues.json` 对录屏及内容绑定增强层执行完全相同的缩放、裁切和位移；不得为竖版重新标注点击、重新画关注框或重新铺音效。标题、字幕和外层状态标签属于输出版式，可在同一事件时间点重新渲染。具体遵循 [xhs-portrait-composition.md](xhs-portrait-composition.md)。纯黑整体缩放仅在用户明确要求旧兼容模式时使用。

矢量框、圆角、文字和勾号统一在2倍分辨率绘制后用 Lanczos 缩小。禁止先生成低分辨率PNG再放大，否则会产生锯齿、虚边和文字发糊。

### 4.2 关注框

- 蓝色框：输入框、按钮、搜索关键词和下一步操作。
- 绿色框：报告、数据包、图表和最终结果。
- 单帧同时最多一个关注框。
- 框必须跟随目标出现与移动；目标被裁掉或遮住时立即结束。
- 不允许框住整张页面，也不允许提前框住下一步。
- 关注框不能覆盖统一底部字幕区域。

### 4.3 点击波纹

- 只跟真实鼠标点击，持续0.45秒。
- 中心点对齐鼠标热点，不对齐光标图形的左上角。
- 一般只强化关键点击；普通浏览点击不加。

### 4.4 状态标签

- 统一使用“检索、采集、清洗、校验、分析、生成、导出”等完整动词。
- 标签使用黑体 W6 字重。必须先测量“图标宽度＋固定间距＋实际文字宽度”，再把整个内容组水平居中；垂直方向使用字体度量的 middle 锚点，禁止用猜测的固定 `y` 偏移。
- 勾号必须用圆端、圆连接的矢量路径绘制，不使用 `✅`、`✓` 等字体或 Emoji 字形；图标与文字间距固定，不使用额外字间距。
- 当前阶段为蓝色，已完成阶段为绿色，未开始阶段为深灰色。
- 状态标签优先放顶部安全区；若遮挡产品重要控件，移至内容区空白处。
- 标签切换必须与真实状态或配音关键词同步。

### 4.5 完成反馈

完成反馈分三级，不能混用：

1. 微反馈“已完成”：用于复制、保存、小步骤确认。
2. 任务反馈“任务完成”：用于单个分析任务结束。
3. 最终反馈“成果已交付”：用于报告、数据包等主要成果全部出现。

使用白色矢量勾号和深绿色底，不用 Emoji、发光粗边、拟物按钮或模糊阴影。完成标签出现时，先测量图标与文字的组合宽度，再将组合整体居中；文字、图标、圆角和内边距必须使用视觉参数文件中的固定值。

### 4.6 进度与等待

进度视觉只在确有等待且无法剪掉时使用。优先显示原产品的真实进度；增强层只做轻量提示，不伪造百分比，不虚构“已完成”的步骤。

## 5. 音画同步流程

1. 完成叙事剪辑、画面选段和速度调整。
2. 固定16:9母版时间线。
3. 完成配音与字幕，并确认字幕不再变更。
4. 按关键动作生成候选时间点。
5. 在关键点前后逐帧检查，写入 `enhancement-cues.json`。
6. 根据 cue 渲染透明视觉覆盖层。
7. 使用时间线合成脚本生成独立 `enhancement-sfx.wav` 和质检报告。
8. 将配音、保留的原声和音效混合；最后再派生3:4版本。

若画面、配音或剪辑点发生变化，只修改受影响的 cue、视觉覆盖层片段和对应音效片段，再重新合成；不需要从原素材完全重做。

## 6. 混音与输出

- 音效库：48 kHz、单声道、PCM16 WAV。
- 成片：AAC 48 kHz；视觉输出保持母版帧率。
- 配音始终是第一优先级。配音出现时，UI音效应明显低于人声。
- 重要完成音附近可将原声或环境声局部降低1–2 dB，避免把完成反馈埋住。
- 音效独立轨最终峰值不得超过 -1 dBFS；合成到成片后仍需检查总峰值和削波。
- 点击、键盘和进度脉冲不要用同一响度；键盘声应最轻，最终交付声最明确。

示例调用：

```bash
python scripts/build_product_demo_sfx_library.py
python scripts/compose_product_demo_sfx_track.py \
  assets/enhancement-cue-sheet.example.json \
  --preset clear \
  --output enhancement-sfx.wav \
  --report enhancement-sfx.json
```

## 7. 质量检查

逐项检查：

- 点击声是否落在真实点击瞬间，误差不超过2帧；
- 键盘声是否只覆盖真实输入区间；
- 输入完成声是否与最终文字显示相差不超过0.15秒；
- 状态标签是否与画面状态和配音一致；
- 结果音是否晚于结果稳定出现，而不是早于它；
- 最终成功音是否晚于报告、数据包等承诺成果完整出现；
- 关注框是否跟随正确目标，且未遮挡字幕；
- 同屏是否只有一个关注框；
- 按钮文字是否居中，图标、文字、边距是否统一；
- 标签是否确实使用 W6 字重，而非因字体集合索引错误回退到 W3；
- 勾号是否为2倍画布上的矢量路径，而非 Emoji 或低分辨率字体符号；
- 圆角和边框是否清晰，无拉伸、锯齿和二次放大；
- 音效是否清楚可辨，又没有压住配音；
- 3:4版本是否与16:9共用同一增强内容母版和事件时间轴；内容绑定组件经过相同取景变换后没有漂移。

每次交付至少保留：

- `enhancement-cues.json`
- `enhancement-sfx.wav`
- `enhancement-sfx.json`
- 透明视觉覆盖层或可重复渲染脚本
- 无平台字幕的16:9增强内容母版
- `framing-cues.json`（需要3:4品牌版时）
- 由同一数据源渲染的16:9横版与3:4品牌版（若用户需要）
