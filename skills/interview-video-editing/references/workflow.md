## 1. 下次开工需要输入什么

### 内容输入

- 原始访谈视频、音频及已有文字记录。
- 人物姓名、经确认的身份、公司或品牌信息。
- 目标受众、发布平台、目标时长、希望观众记住或采取的行动。
- 可选补充材料：录屏、业务数据、报告、现场画面、产品资料。
- 必须保留、不能使用或需要确认的内容。

### 模板输入

- 默认加载本模板，无需每次寻找历史文件。
- 只填写本项目替换项：配色、主题、人物信息、问答内容、素材映射。
- 默认画幅为1080×1440；需要其他画幅时重新布局，共用同一内容时间线。
- 新增要求写成当前项目覆盖项；没有要求改变的组件保持默认。
- 缺少转写、时间码或关键帧时，制作方负责生成，不让用户先手工标完才开始。

## 2. 完整生产流程

### 阶段一：阅读原素材，建立理解

**目的：先知道这个人实际讲了什么，而不是先想画面。**

1. 登记全部素材，核对时长、画幅、帧率、音轨和可访问性；保留原始素材只读。
2. 阅读完整文字记录，按话题形成初步索引；没有记录则转写，已有记录也需与视频核对。
3. 通览视频与声音，识别说话人、机位、表情、语气、重复回答、技术术语和音画问题。长素材可先索引定位，候选使用区间必须连同上下文实际回看、回听。
4. 把内容分为：人物背景、问题痛点、关键判断、解决办法、操作机制、具体场景、数据结果、反思和愿景。
5. 标出潜在金句、具体故事、关键数字、可用人物形象，以及必须核实的表达。

**输出：**素材目录、带时间码的文字索引、话题地图、候选金句表、质量与事实疑点清单。

**进入下一阶段的条件：**已经理解主要内容与人物立场，不只凭几张截图或文字摘要作判断。

### 阶段二：整理访谈主线

**目的：把“受访者说了很多话”变成“观众能跟随的一条论证”。**

1. 明确观众是谁、最关心什么、看完需要理解什么。
2. 用一句话写出全片核心命题，区分“视频主题”与“话题列表”。
3. 从素材中挑出支撑主线的内容，把重复、离题和解释成本过高的枝节移到备选池。
4. 建立逻辑链，例如：原来有什么问题 → 为什么旧做法不够 → 如何改变 → 哪些场景证明有效 → 最终产生什么价值。
5. 给每个大模块写清职责，不能只是“谈数据”“谈AI”；应明确它在证明什么。

**输出：**一句话主旨、受众与观看收益、主线提纲、取舍清单。

**检查：**每一章都能回答“为什么在这里出现，它如何推进主线”。素材不支撑的命题必须调整，不能先定结论再强找证据。

### 阶段三：设计叙事节奏

**目的：先安排观众如何被吸引、理解和说服，再写逐秒脚本。**

默认成片骨架：

**金句开场 → 人物＋主题＋章节入口 → Q1及回答 → Q2及回答 → 代表场景与证据 → 价值收束 → 主题回收。**

1. 金句负责抓人，主题页负责建立“谁在讲、讲什么”，Q卡负责提出明确问题。
2. 每个大模块只设置一个核心问题；回答可拆成多个推进小节，不为每个小节重复插Q卡。
3. 大模块按认知关系排序，不机械照拍摄顺序排列。
4. 每章设计内部推进：提出问题 → 给出方法 → 展示机制或证据 → 落到价值。
5. 规划情绪与密度：开场紧、解释稳、关键结果有强调、结尾收束。正式回答不能照搬金句快闪速度。
6. 估算章节时长及全片时长，优先删冗余，不靠不断加速或缩小字体硬塞。
7. 规划原声人物、业务录屏、截图和解释动画的交替，画面变化由信息推进驱动。

**输出：**章节顺序、各章目的、情绪与节奏图、目标时长预算、拟选金句组合。

**检查：**去掉画面设计后，仅按内容顺序读一遍，也能理解逻辑。

### 阶段四：按主线回源寻找证据

第一阶段是通读与初步索引；这里是带着叙事任务进行精确回源，不是到此才第一次看素材，也不是默认上网找佐证。

1. 为每个论点定位完整原声，记录文件、入点、出点、上下文和可用理由。
2. 对数字、因果、效果、身份等核对原文；区分“受访者的经验判断”与“已有业务材料直接证明的事实”。
3. 寻找对应录屏、操作结果、数据、报告或现场画面。原声证明“他这样说过”，不自动证明所有效果已经客观验证。
4. 真实业务过程优先保留有信息的动作与稳定结果，删除加载、无变化等待和无关滚动。
5. 没有真实画面时，可以使用统一解释动画，但不能把示意动画伪装成真实系统截图或业务结果。
6. 证据不足时记录缺口，补素材、收窄表述或调整主线，不能制造事实。

**证据表字段：**证据ID、对应章节/论点、文件路径、源入点/出点、原话、证据性质、可用画面、裁剪区域、疑点、采用状态。

**输出：**论点—原声—画面映射表、精确候选区间、缺口与替代方案。

### 阶段五：写唯一剪辑执行脚本

脚本必须达到剪辑人员可以逐行执行的粒度，沿用此次交付执行表结构，而不只是旁白稿或提纲。

| 必填列 | 应写清什么 |
| --- | --- |
| 模块/小节ID | 稳定定位编号，不随文案微调变更，不上屏 |
| 成片时间/预计时长 | 策划期是估算；粗剪后回填实际时间 |
| 大模块 | 所属问题与章节 |
| 模块作用 | 本小节在论证中推进哪一步 |
| 上屏文字 | 金句、主题、Q卡、回答顶部观点或结果强调的具体文案 |
| 字幕 | 观众实际听到的原话，按可读语义分句，不以总结替代 |
| 声音 | 原声来源、速度、音乐/音效，以及无人声段 |
| 原素材时间码 | 文件ID与实际源入点/出点；计划期范围需标记待精剪 |
| 证据ID | 原声和业务材料的追溯关联 |
| 素材/画面 | 人物、录屏、截图或模板组件及其调用内容 |
| 剪辑执行 | 切口、衔接、文字时机、强调节点、裁剪与动效 |

两级组织示例：

- 大模块：数据基建；Q：为什么要先让公司掌握自己的数据。
- 小节1：人工取数跟不上规模——建立问题。
- 小节2：RPA批量下载、系统生成报表——给出办法。
- 小节3：从个人汇报转为公司掌握数据——推进到管理价值。
- 小节4：修正一次持续沿用——落到规则沉淀。
- Q卡只出现在大模块入口，四个小节以原声连续推进。

**确认闸门：**确认主线、内容顺序、原声取舍、问题文案与预计时长后，再进入正式剪辑。用户已明确授权按方案执行时不重复询问。只保留一个活跃脚本版本。

### 阶段六：原声粗剪，锁定真实节奏

1. 按执行脚本挑选原声，先剪成无需特效也能听懂的内容版。
2. 删除离题、重复和无效气口，保留关键转折、限定条件和完整发音。
3. 跨段拼接回听上下文，不能制造新含义；去掉原问题后，回答仍要自洽。
4. 金句高密度切，正文默认原速，保留理解和情绪需要的停顿。
5. 逐条校准感知响度；检查底噪、爆音、截字、口型同步与音色差异。
6. 用真实粗剪声轨回填成片时间，建立唯一字幕时间线；不能用字数估算代替实际时长。
7. 若超时，先删低价值内容或压缩重复解释，不改变证据含义。

**输出：**原声粗剪、实际时间线、同步字幕、更新后的唯一执行表。

### 阶段七：套组件精剪

按下文组件C01—C07执行。默认复用本次最终视觉，不从零设计。

先做“金句＋人物主题页＋第一个完整Q&A”的代表样段，确认内容、文字和原声的关系；再批量应用到后续章节。

真实证据画面与解释动画必须按说话时间出现；不要因为组件有空位置就额外填信息。

### 阶段八：预览、质检、交付

1. 检查完整片头及首个Q&A的音画预览；全片较长时检查前约60秒。
2. 检查后续每章代表性关键帧，覆盖最长字幕、最长观点、录屏、数字、图解和结尾。
3. 回听全片，检查原话、证据、切口、字幕与逻辑，而不只看版式。
4. 检查成片解码、画幅、帧率、时长、音轨与素材链接。
5. 修改只更新受影响模块及其下游，不重新做全部内容，也不在不同画幅维护两份脚本。
6. 输出当前最终成片、唯一执行脚本、字幕与时间线、原声剪辑资料、组件与样式配置、质检记录、可复现工程。
